## 1. Executive Summary

### 1.1 核心结论

Askora v0.3 不应试图证明：

> “Adaptive Teaching Policy 在统计意义上普遍优于其他教学方式。”

在当前**单真实用户、低数据量**阶段，这一命题既没有足够统计功效，也没有外部效度基础。

v0.3 应证明的是三个层次完全不同的问题：

| 层级 | 核心问题 | v0.3 能否证明 |
|---|---|---|
| Engineering | 系统是否按设计执行、可 replay、可追踪、无越权 | **可以严格证明** |
| Policy Correctness | 给定 TeachingContext，SYS05 是否遵守冻结规则、不会选择禁止动作 | **可以严格证明** |
| Learning Effect | 对这个用户、这些学习内容，B3 是否比 baseline 出现更好的独立学习结果 | **可以形成个体层面的因果/方向性证据** |
| Population Effect | Askora 是否普遍优于固定策略/LLM Tutor | **不能证明** |

Askora 当前已经冻结：

- 单次 Attempt 不等于长期 mastery；
- assisted success 不等于 independent success；
- answer-exposed success 不能作为高权 mastery evidence；
- stable mastery 需要跨时间、独立提取和迁移证据；
- TeachingAction 必须 deterministic、versioned、replayable；
- engagement、聊天时长、点赞不能作为学习效果主要目标。

对应当前仓库：

- `docs/specs/systems/03-learner-model.md`
- `docs/specs/systems/04-assessment.md`
- `docs/specs/systems/05-teaching-policy.md`
- `docs/specs/quality/observability-standard.md`

因此 DR-03-04 推荐冻结如下评估架构：

```text
Layer 1 — Offline Policy Verification
Scenario Gold Set
→ Hard Constraint Tests
→ Transition Replay
→ Metamorphic / Property Tests
→ Synthetic Learner Stress Tests

Layer 2 — Real-user Learning Measurement
Teaching Episode
→ Immediate Independent Check
→ Delayed Independent Check
→ Near Transfer
→ Optional Far Transfer
→ Efficiency

Layer 3 — N-of-1 Comparative Experiment
Matched Learning Activities
→ randomized B2 / B3 assignment
→ identical assessment/evidence/model stack
→ paired outcomes
→ repeated blocks
→ individual-level evidence

Layer 4 — Evolution Gate
Evidence sufficient?
→ keep deterministic policy
→ refine heuristic weights
→ supervised outcome model challenger
→ only much later consider Contextual Bandit
```

### 1.2 最重要的研究依据

经典 ITS 研究表明，自适应计算机辅导总体可以产生真实学习收益。Ma 等人的 2014 meta-analysis 汇总 14,321 名学习者，ITS 相比大班教师教学、普通计算机教学和教材分别取得约 `g=.42/.57/.35` 的优势；VanLehn 的综述也发现成熟 ITS 的平均效果接近一对一人工 tutoring。

但这些结果只能证明：

> **ITS 可以有效。**

不能证明：

> **Askora 当前 adaptive policy 已经有效。**

生成式 AI Tutor 的最新实验证据进一步说明：

> **当前任务表现提高与真实学习提高可以方向相反。**

Bastani 等人在近千名高中数学学生上的随机实验中发现，普通 GPT 接口显著提高练习阶段表现，但移除 AI 后，学生独立考试成绩反而低于无 AI 控制组；加入教学护栏后，这一损害基本消失。

因此 Askora 的评估原则应冻结为：

> **Learning must be measured after assistance is withdrawn.**

### 1.3 v0.3 推荐主实验

在线真实用户实验不应同时跑 B0/B1/B2/B3 四个 arm。

最有信息价值的是：

```text
Primary comparison:

B2 = LLM 自由选择教学方式
vs.
B3 = Askora deterministic Adaptive Teaching Policy
```

但 B2 仍必须位于 Askora hard policy shield 内，不能为了实验允许答案泄漏或明显错误教学。

B0 固定 Direct Instruction 和 B1 固定 Socratic 应主要用于：

- Offline Gold Set；
- targeted benchmark；
- 特定内容类别的小规模辅助实验。

### 1.4 v0.3 最推荐 primary outcome

产品层面保留四个核心 outcome family：

1. 无提示独立成功；
2. 延迟保持；
3. 迁移；
4. 单位学习时间能力增益。

但**每个具体实验应提前指定一个 primary outcome**，避免看到结果后选择最有利指标。

DR-03-04 推荐 B2 vs B3 主实验：

> **Primary：7±2 天后的无提示独立表现。**

其余作为 secondary/co-primary diagnostics：

- next independent success；
- 24–72h delayed recall；
- near transfer；
- time to independent success；
- learning gain / active learning minute。

7 天并不是科学上的固定魔法数字，而是 v0.3 工程窗口。真正数据必须保存实际 delay 秒数。间隔效应研究表明，适当间隔与目标保持期限存在系统关系，并不存在一个适用于所有学习任务的唯一延迟。

## 2. Askora Evaluation Objective

Askora 的真正优化目标不是：

```text
maximize correct answer now
maximize conversation length
maximize engagement
maximize user satisfaction
```

而是：

```text
TeachingAction
→ learner can subsequently perform independently
→ ability survives delay
→ ability transfers to novel contexts
→ this improvement is achieved efficiently
```

因此应明确区分：

### 2.1 Performance

学习者在有系统帮助时完成任务的能力。

### 2.2 Learning

帮助撤除以后仍然发生的、相对持久的能力变化。

### 2.3 Retention

能力跨时间保持。

### 2.4 Transfer

能力跨题目、表征、情境或领域边界迁移。

这与 Askora 当前产品定位完全一致：平台不是“更会回答问题的聊天工具”，而是以长期保持、独立完成和迁移能力为目标的个人自适应学习系统。

## 3. Evidence Review

### 3.1 Immediate performance ≠ learning

这是 DR-03-04 最重要的实验原则。

生成式 AI 尤其容易造成：

```text
high assisted performance
+
low cognitive effort
+
high answer exposure
=
false impression of learning
```

Bastani 等人的实验直接展示了这种分离。

2025 年 Harvard 物理课程的 AI Tutor crossover RCT 则展示了另一面：经过精心设计、带明确 scaffolding 和教师编制 prompt 的 AI tutor 可以实现更高即时 learning gain，同时降低 time-on-task。但该研究作者也明确把长期 retention 作为后续研究方向，因此不能直接推断延迟保持优势。

**Evidence Strength：High**  
**Applicability to Askora：Direct**

结论：

> Askora 的 primary measurement 必须发生在帮助撤除之后。

### 3.2 Delayed retrieval

Psychological Bulletin 的课堂 retrieval/testing meta-analysis 汇总大量研究，显示课堂 retrieval practice 相比对照总体具有中等量级的学习优势，并受到反馈、重复次数、测试形式与时间等因素调节。

另一项系统综述的课堂实验同样表明 retrieval practice 在不同教育阶段、内容和测试延迟下通常产生正向效果。

因此 Askora 不能只问：

> “刚才会了吗？”

还必须创造：

```text
new opportunity
+
no answer exposure
+
no hint
+
meaningful delay
```

**Evidence Strength：High**  
**Applicability to Askora：Direct**

### 3.3 Transfer

Pan & Rickard 对 test-enhanced learning transfer 的 meta-analysis 显示总体存在正向 transfer benefit，但不同 transfer 类型差异明显。

真实课程研究也持续显示：

```text
isomorphic > near transfer > far transfer
```

far transfer 的收益明显更不稳定。

因此 Askora 不得将：

```text
换一道数字不同的同构题
```

称为强迁移证据。

推荐定义：

#### Near transfer

核心知识组件、原理基本不变，但至少改变：

- surface context；
- numerical values；
- representation；
- problem wording；
- solution path presentation。

#### Far transfer

要求学习者在明显不同：

- context；
- representation；
- task structure；
- application domain；

中识别并重新使用同一深层原理。

**Evidence Strength：High for near transfer / Medium for far transfer**  
**Applicability to Askora：Direct**

### 3.4 Assistance dilemma

ITS 文献长期存在 Assistance Dilemma：

> 太少帮助可能造成无效挣扎；太多帮助可能造成依赖和浅层成功。

帮助行为本身也不是 learning outcome。既有 Help Tutor 研究表明，系统可以改善学习者使用帮助的方式，但这并不自动转化为更好的领域学习结果。

因此：

```text
fewer hints ≠ better learning
more hints ≠ worse learning
```

真正应测：

```text
assistance
→ later independent success
```

DR-03-01 已冻结相同原则。

**Evidence Strength：High**  
**Applicability to Askora：Direct**

### 3.5 False mastery

Askora 当前 SYS03 已明确：

- single immediate success 不直接 stable mastery；
- assisted success 与 independent success 权重不同；
- answer-exposed evidence 不应晋升 stable mastery；
- stable mastery 应要求 delayed evidence；
- transfer mastery 需额外 transfer evidence。

因此 false mastery 的核心不是“模型概率偏高”，而是：

> 系统已经做出高置信、稳定掌握声明，但后续合格的独立证据快速推翻了这一判断。

这必须成为 v0.3 真实 telemetry，而不是只检查 learner-model prediction accuracy。

### 3.6 Synthetic learner 的边界

模拟学习者适合测试系统结构，但不能成为真实教学有效性证据。

ITS evaluation literature 已指出：simulated learner 可以扩展测试规模，但容易因为 simulator 与 tutoring environment 共用假设而产生过拟合和虚假学习预测。

2026 年针对 LLM simulated students 的系统评估进一步发现，简单 prompting 构造的模拟学生在语言、行为和认知一致性方面表现较差，即使监督训练后仍有明显限制。

因此：

**Synthetic Learner 可以测试：**

- state machine robustness；
- transition liveness；
- oscillation；
- impossible paths；
- failure escalation；
- policy workload；
- deterministic replay。

**不能证明：**

- 人类真的学得更好；
- hint fading 真能改善 retention；
- B3 比 B2 学习效果更强；
- mastery threshold 有心理学真实性。

**Evidence Strength：High**  
**Applicability to Askora：Direct**

## 4. Learning Outcome Hierarchy

推荐冻结四层 Outcome Hierarchy。

### 4.1 Primary Learning Outcomes

#### P1 — Delayed Independent Performance

```text
delayed_independent_score
```

条件：

- `answer_exposure = NONE`；
- `hint_level = NONE`；
- 新 assessment item；
- assessment confidence 达标；
- delay 显式记录。

#### P2 — Independent Transfer

分别记录：

```text
near_transfer_success
far_transfer_success
```

不得合并。

#### P3 — Independent Capability Gain

```text
ΔIndependentScore
=
PostIndependentScore - PreIndependentScore
```

#### P4 — Learning Efficiency

推荐两个指标同时存在：

```text
time_to_first_clean_independent_success
```

以及：

```text
independent_gain_per_active_minute
=
ΔIndependentScore / active_learning_minutes
```

后者必须同时报告 numerator 与 denominator，防止系统通过缩短教学时间人为提高比率。

### 4.2 Secondary Learning Outcomes

- next independent success；
- 24–72h retention；
- 28-day retention（可选）；
- immediate independent post-test；
- misconception recurrence；
- repeated independent success；
- time to stable mastery；
- relearning speed。

### 4.3 Process Diagnostics

这些只能解释“为什么”，不能证明 learning：

- hint requests；
- hint level；
- answer exposure；
- scaffold level；
- scaffold fading rate；
- strategy switches；
- repeated failure count；
- Socratic turns；
- worked-example exposure；
- learner response latency；
- policy fallback；
- user override。

尤其：

> hint dependency 是 process diagnostic，不是最终 outcome。

### 4.4 Safety / Trust Guardrails

- hard policy constraint violations；
- answer leakage；
- assessment contamination；
- unsupported citation；
- hallucinated source attribution；
- model override attempts；
- grader disagreement；
- system failure misclassified as learner failure；
- false mastery promotion；
- experiment opt-out violation。

这些属于：

```text
must-not-regress metrics
```

而不是 reward。

### 4.5 normalized gain

可以保存：

```text
g = (post - pre) / (max - pre)
```

但不应成为 Askora primary metric。

normalized gain 的统计性质在教育测量文献中存在持续争论。Askora 单用户、小样本、容易出现 ceiling effect，因此应优先保存：

```text
raw pre
raw post
raw difference
item difficulty bucket
independence
delay
```

normalized gain 只作描述性 projection。

## 5. Offline Policy Evaluation

严格说，Askora v0.3 当前还不具备 RL 文献意义上的 causal Offline Policy Evaluation 条件。

DR-03-03 已明确：

- behavior policy 是 deterministic；
- 没有广泛随机 action coverage；
- 没有真实 action propensity；
- delayed outcome 尚未稳定；
- action support/overlap 不足。

因此推荐正式命名为：

> **Offline Policy Verification & Evaluation（OPVE）**

而不要声称已经实现 IS/IPS/SNIPS/DR/FQE 等 OPE。

### 5.1 OPVE-0 Contract Verification

验证：

```text
TeachingContext
PolicyVersion
StrategyVersion
TeachingAction
DecisionTrace
OutcomeLink
```

的 schema、version、immutability 和 replay。

### 5.2 OPVE-1 Scenario Replay

每个 scenario 建议保存：

```text
ScenarioCase {
    scenario_id
    TeachingContext
    policy_version

    must_be_feasible[]
    forbidden_actions[]
    acceptable_actions[]

    required_reason_codes[]
    required_transition[]
    forbidden_state_mutations[]

    evidence_strength
    provenance
}
```

注意：

> Gold Set 不应该总是指定唯一 `expected_action`。

因为多个教学动作可能都合理。

应该区分：

```text
FORBIDDEN
ACCEPTABLE
PREFERRED
```

只有 deterministic regression snapshot 才要求 exact action。

### 5.3 OPVE-2 Sequential Transition Replay

不能只测试单一步骤。

必须测试：

```text
Context0
→ Action0
→ Outcome0
→ Context1
→ Action1
→ Outcome1
→ ...
```

重点检查：

- repeated failure 是否退出；
- scaffold 是否只升不降；
- assisted success 是否过早晋级；
- independent success 后是否 fading；
- misconception evidence 是否触发合理 remediation；
- delayed success 是否允许进入 transfer；
- state 是否来回 oscillate。

### 5.4 OPVE-3 Property / Metamorphic Tests

比固定 example 更重要。

建议至少冻结以下性质。

#### Determinism

```text
same context
+ same policy version
+ same experiment assignment
→ same TeachingAction
```

#### Assistance monotonicity

在没有新负面证据情况下：

```text
more independent success
MUST NOT
cause unexplained scaffold increase
```

#### Exposure monotonicity

```text
more answer exposure
MUST NOT
increase independent-mastery evidence
```

#### Confidence conservatism

```text
lower learner-state confidence
MUST NOT
cause more aggressive high-confidence personalization
```

#### Hard constraint dominance

改变 weighted score：

```text
MUST NOT
revive forbidden action
```

### 5.5 OPVE-4 Baseline Differential Replay

将同一个 Scenario Set 输入：

```text
B0
B1
B2
B3
```

比较：

- constraint violation；
- expert acceptable-action membership；
- answer exposure；
- context sensitivity；
- repeated-failure handling；
- scaffold fading；
- policy oscillation。

这里**只能比较 policy behavior，不能比较真实 learning effect**。

### 5.6 OPVE-5 Synthetic Learner Stress Test

推荐至少构造以下 adversarial learners：

```text
L0_ALWAYS_FAIL
L1_HINT_DEPENDENT
L2_SUCCESS_ABOVE_SCAFFOLD_K
L3_PERSISTENT_MISCONCEPTION
L4_DELAYED_FORGETTING
L5_TRANSFER_FAILURE
L6_NOISY_PERFORMANCE
L7_DIRECT_ANSWER_SEEKER
L8_LOW_CONFIDENCE_STATE
```

验证：

- infinite loop；
- unreachable mastery；
- oscillation；
- repeated-failure ceiling；
- excessive workload；
- impossible transition；
- policy fallback。

不得生成：

```text
"synthetic learner improved 15%"
```

并将其称为学习效果。

## 6. Gold Set / Scenario Replay

### 6.1 Gold Set 分三级

#### G0 — Constraint Gold

来源：

- hard constraints；
- Assessment integrity；
- Answer exposure；
- architecture invariants。

特点：

```text
无专家自由裁量空间
必须 100% 通过
```

#### G1 — Pedagogical Acceptability Gold

来自 DR-03-01/02 研究。

可以存在：

```text
acceptable_actions = [A, B]
preferred_action = A
```

只要求：

```text
selected ∈ acceptable_actions
```

#### G2 — Research / Calibration Set

用于：

- policy weights；
- uncertain thresholds；
- competing strategy hypotheses。

不作为 blocking release gate。

### 6.2 Gold Set 构建原则

建议每个 scenario 记录：

- research rule；
- provenance；
- evidence strength；
- applicability；
- TeachingContext；
- forbidden action；
- acceptable action；
- rationale；
- boundary variants。

对关键 scenario 最理想是：

```text
independent review
→ disagreement
→ consensus OR acceptable set
```

不能为了生成一个“唯一 gold answer”而掩盖教学科学本身的不确定性。

### 6.3 Transition Test Matrix

| Scenario | 应优先允许 | 必须禁止 / 避免 | 核心 invariant |
|---|---|---|---|
| novice | explicit instruction / worked example / guided practice | 高难度无支架连续任务 | novice 获得足够支架 |
| prerequisite gap | prerequisite remediation | 继续原难度机械练习 | 先修缺口优先处理 |
| repeated failure | 增加支架/换表征/讲解 | 无限重复同一 Socratic probe | failure loop 有上限 |
| misconception | targeted remediation / counterexample / diagnostic | 只做普通重复练习 | misconception 改变 remediation |
| assisted success | fading + independent verification | stable mastery promotion | assisted ≠ independent |
| independent success | reduced scaffold / retrieval | 无理由增加支架 | 独立成功推动 fading |
| delayed success | retained/retrieval/transfer candidate | 回到高支架默认路径 | delayed evidence 权重大 |
| transfer success | lower scaffold / completion signal | 无依据重新教学 | transfer 是高质量 evidence |
| user asks answer | bounded direct explanation | assessment 中泄露答案 | request 不绕过 shield |
| low confidence | diagnostic / conservative action | 高置信个性化干预 | uncertainty → conservatism |
| no-hint assessment | assessment-safe action | solution/hint exposure | assessment integrity |
| answer-exposed success | later independent validation | stable mastery promotion | answer exposure 必须留下债务 |

上述矩阵与当前 SYS03/SYS04/SYS05 的职责划分一致。

## 7. Baseline Design

### 7.1 B0 — Fixed DIRECT_INSTRUCTION

所有合格教学上下文默认直接讲解。

价值：

- 最简单 baseline；
- 测试 adaptivity 是否真的比“一直讲”有价值；
- 对 novice 可能本身很强，因此是重要 challenger。

缺点：

- 对 retention/transfer/fading 不自然；
- 与 B3 差异非常大，难定位收益到底来自哪个组件。

### 7.2 B1 — Fixed Socratic Tutor

所有上下文尽量采用 Socratic probing。

价值：

- 直接测试 DR-03-01 的关键判断：**永久 Socratic 并非合理默认策略**；
- 对 repeated failure / novice 是很好的 stress baseline。

不适合作为长期唯一主 baseline。

### 7.3 B2 — Free LLM Tutor

推荐严格定义为：

```text
same TeachingContext
same strategy/action vocabulary
same evidence
same model snapshot
same retrieval
same assessment
same generation pipeline
same hard policy shield

difference:
LLM chooses TeachingAction
```

而不是让另一个 ChatGPT 会话自由发挥。

最合理的实现概念是：

```text
TeachingContext
→ LLMStrategySelector
→ structured action candidate
→ Hard Policy Shield
→ canonical execution
```

这样 B2 与 B3 的核心差异才真正是：

```text
LLM judgment
vs
deterministic policy
```

### 7.4 B3 — Askora deterministic Adaptive Teaching Policy

即 DR-03-03：

```text
hard constraints
→ stage / guards
→ candidates
→ weighted score
→ transition gate
→ deterministic tie-break
```

### 7.5 哪个 baseline 最有信息价值

排序：

```text
#1 B2 vs B3
#2 B0 vs B3
#3 B1 vs B3
```

原因：

真正需要验证的产品假设是：

> “一个显式、deterministic、可解释的 adaptive policy 是否比让 LLM 自己决定怎么教更好？”

因此 v0.3 不需要四 arm 同时上线。

推荐：

```text
Offline:
B0 + B1 + B2 + B3

Real-user primary experiment:
B2 vs B3

Optional targeted experiment:
B0 vs B3
B1 vs B3
```

## 8. N-of-1 Evaluation

### 8.1 为什么传统 ABAB 不适合直接复制

医疗 N-of-1 常用：

```text
A → B → A → B
```

并依靠 treatment withdrawal / washout。

CENT 标准明确要求考虑：

- carryover；
- period effects；
- within-subject correlation。

教育学习存在一个根本问题：

> **learning 通常不可 wash out。**

一个知识点在 B 条件下已经学会后，不可能恢复到 A 前的“未学习”状态。

因此：

```text
same KC:
A → B → A → B
```

不适合 Askora 的主因果实验。

### 8.2 推荐：Matched-Content Randomized N-of-1

实验单元不是“时间段”，而是：

> **尚未掌握的、彼此独立但难度匹配的 LearningActivity。**

例如：

```text
Pair 01:
Activity A → B2
Activity B → B3

Pair 02:
Activity C → B3
Activity D → B2
```

每个 pair 要尽量匹配：

- prior knowledge；
- content complexity；
- knowledge type；
- estimated difficulty；
- expected learning time；
- assessment format。

condition order 随机/counterbalanced。

### 8.3 单个 Episode

```text
Pretest
↓
Experiment Assignment
↓
Teaching Episode
↓
Immediate NO-HINT Independent Check
↓
24–72h Delayed Check
↓
7±2d Delayed Independent Check
↓
Near Transfer
↓
Optional Far Transfer
```

所有 measurement 必须使用：

- unseen item；
- no answer exposure；
- no hint；
- fixed rubric/version。

### 8.4 推荐实验规模

作为 **v0.3 工程起点，而不是统计学定律**：

```text
8–12 matched pairs
=
16–24 real learning episodes
```

比只做两三个 case 更有价值，同时不会假装获得群体级 statistical power。

### 8.5 分析方式

优先展示：

- 每一对 raw outcomes；
- paired difference；
- win / tie / loss；
- median paired difference；
- mean paired difference；
- uncertainty interval；
- time-to-independent difference。

如果 condition assignment 随机，可进一步使用：

- exact randomization test；
- permutation test；
- Bayesian paired model。

不要首先追逐：

```text
p < .05
```

单用户阶段更重要的是：

```text
effect magnitude
direction consistency
replication across blocks
absence of harm
```

WWC 的 single-case methodology 同样把重复测量、实验操纵和 replicated functional relation 视为单案例因果证据的核心，而不是简单依赖一次 pre/post。

### 8.6 Switchback

只适合：

```text
different, exchangeable learning episodes
```

不适合：

```text
same skill repeatedly switch B2/B3
```

因为学习 carryover 无法清除。

因此 Askora 可以使用：

```text
episode-level switchback
```

不能把传统电商 switchback 原样套用。

### 8.7 Interrupted Time Series

例如：

```text
Policy v0.2
────────────
Policy v0.3
```

观察长期：

- independent success；
- retention；
- hint dependency。

它可以形成：

**Weak / supporting evidence**

但不能可靠排除：

- 学习内容变化；
- 用户能力自然增长；
- 时间趋势；
- 测量变化；
- model version 变化。

因此不能作为 v0.3 主因果证据。

### 8.8 Repeated Measures

这是 Askora 应默认采用的数据形态：

```text
one learner
× many KCs
× many episodes
× many delays
```

但 repeated measures 本身**不是实验设计**。

### 8.9 Sequential Experiment

Askora 可以逐 block 累积数据：

```text
Block 1
→ review safety
→ Block 2
→ review safety
→ Block 3
```

但不应每两三个 episode 就：

```text
peek p-value
→ stop when significant
```

未来若需要更正式在线实验，可以借鉴 micro-randomized trial 对：

- decision point；
- intervention option；
- proximal outcome；
- distal outcome；

的分离思想。

v0.3 不需要实现完整 MRT。

### 8.10 “可以证明 / 弱证据 / 不能证明”

#### 可以严格证明

- deterministic replay；
- hard constraint compliance；
- forbidden action never selected；
- no-answer leakage tests；
- trace completeness；
- policy transition correctness。

#### 可以形成较强个体因果证据

在 randomized matched N-of-1 下：

> 对当前用户和测试内容，B3 相比 B2 对 delayed/transfer outcome 的因果优势。

但结论必须限定：

```text
this user
this content distribution
this time period
this implementation
```

#### 可以形成弱证据

- pre/post improvement；
- policy-version before/after；
- interrupted time series；
- observational replay；
- expert preference；
- synthetic learner。

#### 完全不能证明

当前 v0.3 无法证明：

- 对其他人也有效；
- 所有学科有效；
- far transfer 普遍提高；
- B3 优于人类优秀 tutor；
- 某个 policy weight 是全局最优；
- 某个 mastery threshold 是科学常数；
- 某个单一 TeachingAction 导致数天后的全部学习结果；
- Contextual Bandit/RL 会更好。

## 9. Delayed Outcome Attribution

### 9.1 为什么 last-touch attribution 错误

真实轨迹可能是：

```text
t0 DIRECT_INSTRUCTION
t1 GUIDED_PRACTICE
t2 ERROR_REMEDIATION
t3 FADED_PRACTICE
t4 independent success
...
t+7d delayed success
```

不能写：

```text
delayed success
→ attributed to t3
```

因为 t0–t3 全部参与了学习。

### 9.2 推荐三个实体

#### TeachingEpisode

一个相对完整的教学闭环：

```text
episode start
→ one or more TeachingActions
→ first independent checkpoint
→ episode end
```

#### LearningTrajectory

跨多个 episode 的 KC 轨迹：

```text
Episode 1
→ Review
→ Episode 2
→ Delayed Assessment
→ Transfer
```

#### OutcomeObservation

实际测量：

```text
Immediate
Delayed
Transfer
```

### 9.3 Attribution Scope

建议明确保存：

```text
ACTION_DIRECT
EPISODE_ASSOCIATED
TRAJECTORY_ASSOCIATED
EXPERIMENTALLY_CAUSAL
UNATTRIBUTABLE
```

#### ACTION_DIRECT

只有：

```text
TeachingAction
→ no intervening teaching
→ immediate attempt
```

才适合。

#### EPISODE_ASSOCIATED

next-independent outcome 默认属于整个 episode。

#### TRAJECTORY_ASSOCIATED

delayed retention 默认关联：

```text
since_last_clean_checkpoint
```

期间全部有效 exposure。

#### EXPERIMENTALLY_CAUSAL

只有随机 experiment assignment 才可以升级到因果解释。

### 9.4 Delayed Outcome 最小数据

```text
OutcomeObservation {
    outcome_id
    learner_id
    knowledge_unit_id
    learning_activity_id

    episode_id
    trajectory_id

    outcome_type
    assessment_item_version

    score
    correctness
    independence
    assistance_level
    answer_exposure

    scheduled_delay
    actual_delay

    transfer_distance

    exposure_set_ids[]
    intervening_exposure_count

    external_exposure_known
    contamination_status

    experiment_id
    variant

    assessment_confidence
}
```

### 9.5 Clean vs contaminated outcome

如果 7 天中学习者重新看过答案：

```text
delayed outcome ≠ clean retention
```

不要删除。

保存：

```text
CLEAN
INTERVENING_REVIEW
ANSWER_EXPOSED
EXTERNAL_EXPOSURE_UNKNOWN
```

这比“假装所有 delayed outcomes 都可比较”更科学。

## 10. Safe Experiment Framework

### 10.1 Safe Experiment Set

只有满足以下条件才能进入 randomized comparison：

```text
>= 2 pedagogically acceptable variants
AND
all variants pass hard constraints
AND
same assessment integrity
AND
same answer exposure ceiling
AND
no critical safety/accessibility conflict
```

### 10.2 禁止随机化的情况

不得为了实验随机：

- assessment answer exposure；
- 明显错误答案；
- severe prerequisite gap 下的高难独立任务；
- repeated failure 后继续无限无支架；
- 已确定高置信 misconception 时的明显不相关教学；
- 用户 accessibility requirement；
- security / privacy rule；
- citation fabrication；
- grader-only reference leakage。

### 10.3 B2 也必须经过 Hard Policy Shield

“Free LLM Tutor”不能意味着：

```text
LLM has unlimited freedom
```

正确定义：

```text
LLM proposal
→ hard shield
→ execute only safe action
```

这样既符合教育伦理，也能真正测量：

> policy intelligence 的差异，而不是安全底线差异。

### 10.4 Opt-out

真实用户必须能够：

```text
disable experiments
```

并保存：

```text
experiment_opt_out
```

不得把用户退出当作 learner failure。

### 10.5 Stopping Criteria

#### Immediate stop

以下任一发生：

- hard policy violation；
- answer leakage；
- experiment assignment bypass；
- model successfully overrides TeachingAction；
- corrupted outcome attribution；
- assessment integrity failure。

#### Arm review / degradation stop

如果一个完成 block 出现：

```text
material degradation
in delayed independent performance
OR transfer
OR answer exposure
OR false mastery
```

并超过预先配置的 practical harm margin，则暂停该 experimental arm。

margin 必须：

```text
versioned
predeclared
```

不得看到结果后修改。

### 10.6 Experiment assignment ≠ action propensity

如果：

```text
B2 vs B3
randomized 50/50
```

正确记录：

```text
variant_assignment_probability = 0.5
```

并不意味着：

```text
TeachingAction.action_propensity = 0.5
```

B3 内部仍为 deterministic policy。

只有未来在 hard-filter 后真正随机选择：

```text
Action A vs Action B
```

才能产生合法 action propensity。

这一点必须继承 DR-03-03 的数据契约原则。

## 11. Observability Requirements

Askora 当前 observability standard 已要求关键学习结果能够追踪到：

```text
request
→ domain decision
→ model/tool
→ AssessmentResult
→ LearnerEvidence
→ state update
```

并已经把 independent success、hint dependency、delayed retention、transfer、false mastery 纳入学习指标。

DR-03-04 建议进一步形成以下 observation contract。

### 11.1 ExperimentAssignment

```text
experiment_id
design_version
block_id
pair_id

eligibility_reason
variant
assignment_method
assignment_probability
random_seed_reference

assigned_at
opt_out_state
```

### 11.2 Decision Observability

继续记录：

- TeachingContext version；
- feasible actions；
- forbidden actions；
- hard-filter reasons；
- scores；
- tie-break；
- selected TeachingAction；
- transition reason；
- policy version；
- strategy version；
- experiment variant；
- behavior policy type。

### 11.3 Episode Observability

新增：

```text
episode_id
trajectory_id
start/end
knowledge unit
activity
pretest state
TeachingAction ids[]
assessment ids[]
active_learning_time
system_wait_time
completion reason
```

系统 latency 与 learner active time 必须分开。

### 11.4 Outcome Observability

必须支持：

```text
next independent
24–72h delayed
7d delayed
28d delayed
near transfer
far transfer
```

并保存实际：

```text
actual_delay_seconds
```

不能只保存：

```text
delay_bucket = WEEK
```

### 11.5 Assistance Observability

每次 Attempt 至少保留：

```text
hint_level
hint_count
answer_exposure
worked_example_exposure
scaffold_level
user_requested_answer
```

否则无法判断：

```text
correct
```

到底是什么性质的正确。

### 11.6 False Mastery

推荐定义：

```text
false_mastery_promotion_rate
=
stable_mastery promotions
followed by eligible clean contradiction
/
stable_mastery promotions with validation
```

“clean contradiction”可以是：

- delayed independent failure；
- repeated misconception；
- near-transfer failure；

但必须排除：

- invalid assessment；
- technical failure；
- low-confidence scoring。

### 11.7 False Negative Mastery

不要根据一次成功反推 learner model 错误。

建议建立：

```text
false_negative_suspicion
```

当：

```text
model says not mastered
+
multiple distinct independent successes
+
delayed success
+
possibly transfer success
```

持续出现时，才标记 learner model 过于保守。

### 11.8 Metric Versioning

必须新增概念：

```text
outcome_definition_version
```

否则今天的：

```text
independent_success
```

与半年后的定义可能不同，历史实验不可比较。

### 11.9 Privacy

延续当前 OBS 原则：

优先保存：

```text
structured outcome
reason code
item/version reference
hash/reference
```

而不是默认长期保存完整 private conversation。

## 12. v0.3 Proposed Release Gate

建议未来 vertical slice 将验收拆为三个 blocking gate。

### 12.1 Engineering Gate

#### V03-EVAL-E01 — Deterministic Replay

固定：

```text
TeachingContext
policy version
experiment assignment
```

必须 100% replay 同一语义 TeachingAction。

#### V03-EVAL-E02 — Decision Trace Completeness

每个 TeachingAction 可回溯：

```text
input
candidates
hard filters
scores
transition
selection
policy version
```

#### V03-EVAL-E03 — No Policy Bypass

LLM / SYS08 无法提高：

- scaffold；
- answer exposure；
- action semantics；

绕过 SYS05。

#### V03-EVAL-E04 — Assessment Integrity

固定 regression set：

```text
answer leakage = 0
hard constraint violation = 0
```

#### V03-EVAL-E05 — Failure Semantics

- model failure；
- sandbox failure；
- retrieval failure；

均不得生成 learner failure evidence。

#### V03-EVAL-E06 — Test Layers

适用 TEST L0–L6 全部满足当前 `testing-standard.md`。

### 12.2 Policy Correctness Gate

#### V03-EVAL-P01

G0 Constraint Gold：

```text
100% pass
```

#### V03-EVAL-P02

G1 scenario：

```text
selected_action ∈ acceptable_actions
```

所有 forbidden actions：

```text
0 selected
```

#### V03-EVAL-P03

必须覆盖：

- novice；
- prerequisite gap；
- repeated failure；
- misconception；
- assisted success；
- independent success；
- delayed success；
- transfer success；
- user asks answer；
- low confidence；
- no-hint assessment；
- answer-exposed success。

#### V03-EVAL-P04

sequence replay 必须证明：

```text
repeated failure → exit/escalation
independent evidence → fading
answer exposure → independent-validation debt
```

#### V03-EVAL-P05

synthetic learner 长轨迹中：

- 无无限教学 loop；
- 无非法 transition；
- 无无界 scaffold oscillation。

### 12.3 Learning Evidence Gate

这不是要求统计显著。

推荐最低 pilot：

```text
B2 vs B3
8–12 matched pairs
randomized/counterbalanced assignment
```

其中：

- assessment stack 相同；
- model snapshot 相同；
- retrieval evidence 相同；
- hard shield 相同；
- outcome definitions 相同。

至少收集：

```text
Immediate independent
7-day delayed independent
Near transfer
Active learning time
```

#### Pass 建议

必须同时满足：

1. 没有 safety/assessment integrity regression；
2. B3 的 delayed-independent paired outcome 没有 material negative direction；
3. 至少一个核心 outcome 显示一致有利方向：

```text
independent success
OR delayed retention
OR near transfer
OR efficiency
```

4. hint dependency / answer exposure / false mastery 没有恶化；
5. raw pair-level results 可以完整审计；
6. 不把单用户结果描述为 population efficacy。

如果 delayed outcomes 大量缺失，应返回：

```text
LEARNING_EVIDENCE_INSUFFICIENT
```

而不是通过缺失数据推断“有效”。

### 12.4 Engineering / Policy / Learning Gate 必须分离

如果 Engineering + Policy Gate 全部通过，但 Learning Evidence Gate 不通过：

> 不代表系统工程失败。

正确结论应该是：

```text
v0.3 policy implementation is correct,
but learning benefit is not yet demonstrated.
```

继续迭代 deterministic policy，而不是升级更复杂算法。

## 13. Evidence Required for v0.4

进入 v0.4 应满足的不是“用了多久”，而是 evidence maturity。

### 13.1 Policy Evidence

至少两个相对独立 experiment block 中：

```text
B3 vs B2
```

出现同方向 learning signal。

推荐要求：

- delayed independent 有正方向；
- near transfer 不劣；
- efficiency 不明显恶化；
- safety guardrails 无恶化。

### 13.2 Outcome Data Quality

需要足够：

- clean independent outcomes；
- delayed outcomes；
- transfer outcomes；
- intervention exposure records；
- outcome-definition versions。

如果绝大多数结果都是：

```text
assisted success
```

即使日志数量很大，也没有升级算法的数据价值。

### 13.3 False Mastery Evidence

必须知道：

- stable mastery promotion 后多少被 delayed evidence 推翻；
- learner model 是否系统性过于激进；
- 是否存在长期 false-negative。

否则 Teaching Policy 的 personalization input 本身不可靠。

### 13.4 Supervised Outcome Model Readiness

如果未来 v0.4 希望：

```text
heuristic score
→ supervised expected-outcome model
```

至少要做到：

- outcome label 定义稳定；
- action/context feature stable；
- time-based train/test split；
- no outcome leakage；
- calibration evaluation；
- deterministic policy 继续作为 canonical baseline；
- ML model 先以 challenger 存在。

### 13.5 Contextual Bandit Readiness

以下全部出现以前不要进入 Bandit：

```text
safe randomized action opportunities
true action propensities
multiple eligible actions per context
sufficient action overlap
stable delayed reward
reliable transfer outcome
enough effective sample size
```

尤其需要区分：

```text
experiment variant assignment
≠
action propensity
```

当前单用户阶段很可能仍不满足这些条件。

因此最合理的 v0.4 路径很可能是：

```text
deterministic policy
+
better outcome analytics
+
supervised challenger
```

而不是 Bandit。

### 13.6 Far Transfer

far transfer 应持续收集，但**不建议作为进入 v0.4 的 blocking requirement**。

原因：

- 测量成本高；
- item validity 难；
- 学习科学本身就显示 far transfer 比 near transfer 更难稳定获得。

它应作为高价值 exploratory outcome。

## 14. Limitations

### 14.1 单用户无法外推群体

即使 N-of-1 非常严格，也只能支持：

> 对当前用户，在这些任务、时间和系统版本下的个体因果结论。

无法自动推广到：

- 儿童；
- 大学生；
- 不同背景学习者；
- 不同学科；
- 不同语言。

### 14.2 内容匹配本身存在误差

B2/B3 使用不同 LearningActivity 时：

```text
content difficulty
```

无法完全匹配。

因此：

- pretest；
- difficulty bucket；
- paired design；
- multiple replications；

很重要。

### 14.3 测试本身也是教学

retrieval assessment 本身可能产生 learning。

因此 delayed test 不只是“被动测量”，也可能改变未来状态。

关于 testing effect 的研究提醒，direct testing effect 与 forward testing effect 在许多研究中存在混杂。

Askora 因此必须把：

```text
AssessmentAttempt
```

本身记录为 learning exposure。

### 14.4 延迟期间存在外部学习

用户可能：

- 搜索网页；
- 看书；
- 用其他 AI；
- 与他人讨论。

无法完全控制。

只能记录：

```text
known external exposure
unknown contamination
```

而不能假装实验室环境。

### 14.5 B2 自身可能变化

如果底层 LLM model snapshot、system prompt 或 provider 更新：

```text
B2_t1 ≠ B2_t2
```

所以 experiment 必须冻结：

- model；
- prompt；
- tool configuration；
- retrieval configuration。

### 14.6 Pedagogical Gold 不是绝对真理

DR-03-01/02 中很多规则有高质量研究依据，但：

- mastery cutoff；
- failure threshold；
- fading increment；
- strategy weights；

仍然属于版本化工程参数。

它们必须通过真实 Askora 数据逐步验证，而不是被包装成“教育学定律”。

## Final Recommendation

DR-03-04 最终应冻结的原则可以压缩为一句话：

> **Askora v0.3 不以“AI 当下帮用户答得更好”为成功，而以“撤除帮助后，用户能否更快、更久、更独立地解决新问题”为成功。**

对应工程顺序应冻结为：

```text
1. Gold Set 证明规则没有错
2. Scenario / Transition Replay 证明 policy 没有坏
3. Synthetic Learner 证明状态机不会失控
4. B2 vs B3 N-of-1 证明当前用户出现真实学习信号
5. Delayed + Transfer 证明信号不是即时幻觉
6. 数据足够后才允许升级算法复杂度
```

因此，**v0.3 的成功标准不是“Adaptive Policy 已被统计学证明优于所有 Tutor”，而是：**

```text
Engineering Correct
+
Policy Correct
+
No Learning Harm
+
Directional Individual Learning Evidence
+
Correct Experimental Data Foundation
```

只有达到这一层，Askora 才有充分理由进入 v0.4。
