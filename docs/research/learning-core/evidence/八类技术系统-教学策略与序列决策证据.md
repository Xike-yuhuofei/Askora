# 八类技术系统：教学策略与序列决策证据

> 阶段：B｜统一研究资料库

## 1. 研究问题

1. 教学策略选择应从规则走向何种学习型算法？
2. Contextual Bandit、Offline RL、在线 RL 各适合解决什么问题？
3. 如何避免用短期 engagement reward 伤害长期学习？
4. “教学动作选择”与“学习内容/任务排序”如何分离？

## 2. 教学策略是受约束决策问题

`Askora 设计选择`

TeachingAction selection 可抽象为：

```text
context/state
→ feasible action set
→ hard constraints
→ action scoring/policy
→ selected action
→ outcome evidence
→ later state update
```

候选动作例如：

```text
EXPLAIN
SOCRATIC_QUESTION
WORKED_EXAMPLE
FADED_EXAMPLE
PRACTICE
HINT_L1/L2/L3
DIAGNOSTIC_PROBE
REVIEW
TRANSFER_TASK
METACOGNITIVE_REFLECTION
```

**核心原则**：算法只能在教学安全和课程约束允许的动作集合中优化。

## 3. 为什么 MVP 应先使用规则 + 状态机 + 评分

`Askora 设计选择`

规则/状态机的价值：

- 冷启动无需历史策略日志；
- 教学边界可审计；
- 易表达“无提示测试不得暴露答案”等硬约束；
- 易回放和定位错误；
- 可作为后续学习型策略的 baseline 和 safety layer。

建议 MVP：

```text
Hard Rules
→ Feasible Actions
→ State Machine Guard
→ Weighted Scoring
→ TeachingAction
```

示例：

```text
if assessment_mode == "independent_test":
    disallow(EXPLAIN, HINT_L2, HINT_L3)

if learner_state.prerequisite_gap_high:
    boost(DIAGNOSTIC_PROBE, PREREQUISITE_REMEDIATION)

if repeated_failure and scaffold_level < limit:
    boost(next_scaffold_level)
```

权重必须版本化，并通过 DecisionTrace 记录。

## 4. 监督学习

`研究证据` + `Askora 设计选择`

当历史数据中存在相对可靠的教学动作结果标签时，可训练：

- success probability model；
- hint need predictor；
- dropout/frustration risk；
- action outcome model。

但纯监督学习会复制历史策略的选择偏差：过去没尝试过的动作缺少反事实标签。

**推荐用途**：预测和候选评分，而不是直接无约束替换 policy。

## 5. Contextual Bandit

Contextual Bandit 每轮观察上下文，选择一个动作并接收相对局部奖励。教育推荐和 curriculum personalization 已存在研究探索，部分工作报告 completion、skill gain 等改善。

- 证据等级：`研究证据`
- 技术可行：高
- 工程成熟：中高
- 教育有效：依奖励定义和场景
- Askora 当前适用：中，需先积累数据

### 5.1 适合的问题

- 同一教学目的下选择不同例子；
- 提示表达方式；
- 两三个教学策略候选之间局部个性化；
- 检索 route/reranker variant；
- 复习任务中的局部排序。

### 5.2 不适合的问题

- 强长期依赖的整条课程规划；
- 当前动作会大幅改变未来状态、而奖励长时间延迟；
- 高风险、不能探索的关键决策；
- 奖励只能用点击/停留时长的场景。

### 5.3 奖励约束

`Askora 设计选择`

奖励优先级：

```text
延迟独立成功 / transfer gain
> 下一次独立成功
> 提示依赖下降
> 形成性表现改善
> engagement / satisfaction
```

后两者不能单独作为长期优化目标。

## 6. Offline RL

Offline RL 在固定历史数据上学习策略，目标是减少在线探索风险。Levine 等综述指出其核心困难包括 distribution shift、extrapolation error 与 off-policy evaluation；CQL 等方法通过保守价值估计减轻对分布外动作的过度乐观。

- 证据等级：`研究证据`（RL 方法）
- 技术可行：高
- 工程成熟：中
- 教育有效：尚不能普遍推断
- Askora 当前适用：低

**前置条件**：

- 足量、版本清楚的历史轨迹；
- 行为策略 propensity/logging；
- 明确状态、动作和延迟奖励；
- 可靠 OPE；
- coverage 足够，不能只从单一规则策略数据学出“新最优策略”。

`Askora 设计选择`：早期先把事件和 DecisionTrace 建好，为未来 Offline RL 准备数据，而不是提前上 RL。

## 7. 受约束在线强化学习

`实验性方案`

长期教学确实具有 MDP/POMDP 特征：当前教学动作会影响未来知识状态、动机与选择。但直接在线 RL 的风险包括：

- 学习结果奖励延迟；
- learner state 部分可观测；
- 个体数据少；
- 探索可能伤害真实学习者；
- reward hacking；
- 策略漂移难解释；
- 干预之间存在 carryover。

因此若未来采用，应使用：

```text
Constrained Policy
+ immutable hard rules
+ safe action set
+ conservative exploration
+ kill switch
+ shadow evaluation
+ offline OPE
+ staged rollout
```

当前阶段：**不推荐实施**。

## 8. Reward 设计

`Askora 设计选择`

不能把以下指标作为最终奖励：

- 对话次数；
- session 时长；
- 点击率；
- 连续签到；
- 即时正确率；
- 用户点赞。

它们可能与学习结果相关，也可能冲突。

长期目标函数应更接近：

```text
J =
  w1 * delayed_independent_mastery_gain
+ w2 * transfer_success
+ w3 * time_efficiency
- w4 * hint_dependency
- w5 * overload_or_frustration_risk
```

这些权重仍属于产品价值选择，必须公开版本化并做敏感性分析。

## 9. 反事实评估与实验

学习型策略上线前必须至少考虑：

- IPS / SNIPS；
- Doubly Robust；
- replay / simulator；
- time-split validation；
- policy value confidence interval；
- A/B 或 randomized policy experiment。

`研究者推断`：教育场景中存在强时间依赖，普通随机划分容易泄漏未来行为；优先用户级 + 时间级切分。

## 10. 教学策略 vs 学习路径

`Askora 设计选择`

必须冻结：

```text
4.6 学习路径与任务调度
决定：当前/未来学哪个 LearningObjective / LearningActivity

4.5 教学策略选择
决定：对当前 objective/activity 采用什么 TeachingAction
```

例：

```text
4.6：今天先复习“形式系统”，再学“哥德尔编码”
4.5：当前“哥德尔编码”任务用 worked example 还是苏格拉底追问
```

RL 也不能跨越这条 ownership 边界。

## 11. 算法演进顺序

`Askora 设计选择`

严格采用：

```text
规则
→ 启发式评分
→ 监督预测/排序
→ Contextual Bandit
→ Offline RL
→ 受约束在线 RL
```

升级条件不是“模型更先进”，而是：

1. 当前简单方法遇到可量化瓶颈；
2. 存在足够高质量数据；
3. 新方法离线优于 baseline；
4. 可解释/可回滚；
5. 在线实验有安全边界；
6. 对学习结果而非代理指标有增益。

## 13. 证据缺口

- 教育 Bandit/RL 文献的 reward 和任务差异很大，不能直接迁移参数。
- 延迟保持与迁移作为长期 reward 的大规模在线策略研究仍不足。
- Askora 首先需要高质量 event/decision logging；没有日志覆盖时，Offline RL 的“离线”并不意味着安全可靠。
- 用户可纠正 learner state 后，策略学习如何处理人为状态修正需要专门设计。
