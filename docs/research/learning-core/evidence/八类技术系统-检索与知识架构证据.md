# 八类技术系统：检索与知识架构证据

> 阶段：B｜统一研究资料库

## 1. 研究问题

1. 混合检索、多阶段排序、RAG、GraphRAG、层级检索分别解决什么问题？
2. 哪些技术已经工程成熟，哪些只应按场景启用？
3. 教学检索为何不能只优化 query-document relevance？
4. 如何保证来源、引用、答案泄漏和知识状态可审计？

## 2. 普通 RAG 的正确边界

Lewis 等提出 Retrieval-Augmented Generation（RAG），把外部非参数知识与生成模型结合。其价值在于：

- 让生成依赖可更新的外部资料；
- 减少把所有知识固化在模型参数中的需求；
- 为来源追踪创造条件。

证据等级：`研究证据`  
技术可行：高  
工程成熟：高  
教育有效：不能由 RAG 本身推出。

`Askora 设计选择`：RAG 是**知识供给机制**，不拥有学习者状态、教学策略和掌握判断。

## 3. 稀疏 + 稠密混合检索

### 3.1 BM25

Robertson & Zaragoza 对 BM25/概率相关性框架进行了系统总结。BM25 对精确术语、罕见词、公式符号、专有名词和用户指定原文措辞仍有重要价值。

- 证据等级：`学术共识`（IR 工程）
- 工程成熟：最高
- Askora 当前适用：最高

### 3.2 Dense Retrieval

DPR 等工作证明双编码器 dense retrieval 能有效处理语义匹配和措辞变化。

- 证据等级：`研究证据`
- 工程成熟：高
- 局限：可能忽略精确 lexical signal；领域外 embedding 表现不稳定。

### 3.3 Hybrid Retrieval

`行业实践` + `研究证据`

由于 sparse 与 dense 错误模式互补，MVP 不应“选边站”，而应保留两路召回，再通过融合/重排决策。

`Askora 设计选择`：

```text
BM25
+ Dense Retrieval
→ RRF
→ Cross-Encoder / Late Interaction rerank
→ pedagogical filters
```

## 4. Reciprocal Rank Fusion（RRF）

Cormack、Clarke、Buettcher（2009）提出 RRF，用各列表名次而非原始分数量纲融合多路结果：

```text
RRF(d) = Σ 1 / (k + rank_i(d))
```

- 证据等级：`研究证据`
- 工程成熟：高
- Askora 当前适用：高

优点：

- 不需要把 BM25、向量相似度、图距离先校准到相同量纲；
- 简单稳定；
- 适合作为 Learning-to-Rank 之前的默认融合基线。

## 5. 多阶段重排序

Cross-Encoder / late interaction（如 ColBERT）代表“先高召回、后高精度”的经典多阶段检索思路。

- 证据等级：`研究证据`
- 工程成熟：高
- Askora 当前适用：高

教学检索的重排分数不能只包含语义相关性，应加入：

```text
semantic_relevance
+ lexical_relevance
+ target_concept_coverage
+ prerequisite_fit
+ learner_stage_fit
+ pedagogical_role_fit
+ source_quality
+ citation_quality
- answer_leakage_risk
- redundancy
- cognitive_load_penalty
```

其中后半部分属于 `Askora 设计选择`，需要通过教学结果实验校准。

## 6. GraphRAG

Microsoft Research 的 GraphRAG 公开工作展示了从文本构建实体/关系图并进行局部或全局问题回答的路线，尤其适合跨文档、跨章节聚合与全局主题总结。

- 证据等级：`研究证据` + `行业实践`
- 技术可行：高
- 工程成熟：中高
- Askora MVP 必要性：低到中

**适合 Askora 的问题**：

- 某概念有哪些前置依赖；
- 错误可能来自哪些上游知识断层；
- 跨章节因果/组成/对比关系；
- 从一个知识点扩展到迁移应用。

**不适合默认使用**：

- 精确定义查找；
- 单页局部事实；
- 已知章节内简单引用；
- 对低质量知识图谱进行多跳扩展。

`Askora 设计选择`：GraphRAG 必须回填原始 SourceSpan 证据。图节点/社区摘要本身不能成为不可追溯的事实源。

## 7. 长文档层级检索与 PageIndex 类实践

RAPTOR 等研究通过递归聚类/摘要形成层级树，以支持长文档不同粒度查询。PageIndex 开源项目公开采用文档树/推理式定位路线，强调不完全依赖向量切块。

- RAPTOR：`研究证据`
- PageIndex：`行业实践`

对 PageIndex 项目 README 中的 benchmark 数字，只能视为项目方公开结果，不能当成独立学术共识。

**Askora 设计含义**：

```text
长文档连续论证 / 章节范围定位
→ hierarchy/page tree

跨章节知识依赖
→ graph

局部精确取证
→ lexical + dense
```

三者互补而非替代。

## 8. 知识图谱：规范事实与检索投影必须分离

`Askora 设计选择`

知识图谱最危险的架构错误是把“机器抽取图”直接当作事实真相。Askora 应坚持：

```text
规范内容数据库（事实源）
→ KnowledgeUnit / Concept / PrerequisiteRelation
→ 可重建的 graph projection / vector projection / lexical index
```

必要属性：

- 来源证据；
- 置信度；
- 抽取器/模型版本；
- 审核状态；
- 有效版本范围。

这样才能允许：

- 更新抽取算法；
- 回滚错误关系；
- 比较图版本；
- 重建索引；
- 保留学习历史稳定 ID。

## 9. 检索相关性 vs 教学适用性

这是 Askora 与普通 RAG 的关键区别。

`Askora 设计选择`

用户问“这道题怎么做”时，最相关的文本很可能就是完整答案；但在无提示测试阶段，完整答案是**最不应该送入学习者可见生成路径的材料**。

因此至少分两层判断：

```text
Retrieval Relevance：是否与请求内容相关
Pedagogical Suitability：是否适合当前教学动作、阶段、提示强度和暴露政策
```

检索层不决定 TeachingAction，但必须执行 4.5 传来的教学约束。

## 10. 答案泄漏控制

`Askora 设计选择`

仅靠 Prompt 说“不要透露答案”不足以作为系统边界。控制必须在数据面执行：

```text
候选召回前元数据过滤
→ 重排惩罚
→ EvidenceBundle 选择
→ 生成层输出审查
```

建议暴露级别：

```text
L0 条件/已知事实
L1 方向性线索
L2 局部下一步
L3 关键结构
L4 完整解答
```

教学策略拥有最高允许级别，检索只能收紧不能放宽。

## 11. EvidenceBundle 与 provenance

`Askora 设计选择`

检索层应返回结构化 EvidenceBundle，而不是裸字符串：

```text
证据内容
+ pedagogical_role
+ source anchor
+ relevance
+ confidence
+ exposure level
+ allowed use
+ conflicts
+ missing evidence
+ retrieval trace
```

每个最终引用必须能回溯：

```text
生成陈述
→ EvidenceBundle item
→ KnowledgeUnit/PedagogicalAsset
→ SourceSpan/SourceChunk
→ MaterialRevision
```

## 12. RAG 评价

RAGAS 等工作提供 faithfulness、answer relevance、context relevance 等自动化评价思路；相关综述也显示 RAG 评价需要分别测 retrieval 与 generation。

- 证据等级：`研究证据` / `行业实践`
- Askora 适用：作为工程指标，中高

但这些指标仍不是教育效果。

Askora 评价四层：

1. 检索：Recall@K、MRR、nDCG、coverage；
2. 可信：citation precision/coverage、unsupported claim rate；
3. 教学适配：leakage rate、prerequisite sufficiency、stage fit；
4. 学习结果：下一次独立成功、提示依赖下降、延迟保持、迁移。

## 13. 推荐技术路线

### MVP

`Askora 设计选择`

```text
PostgreSQL 规范内容模型
+ PostgreSQL/FTS 或搜索引擎 BM25
+ 向量索引
+ RRF
+ Cross-Encoder reranker
+ MMR/去重
+ source anchors
+ EvidenceBundle
+ answer leakage policy
```

### 增强版

- 知识图谱邻居/路径召回；
- 长文档层级索引；
- coverage constrained selection；
- retrieval evaluation set；
- 来源冲突模型。

### 成熟版

- Learning-to-Rank；
- 基于学习结果的 rerank features；
- 对“检索路线选择”尝试 Contextual Bandit，但需要安全约束和离线评估。

### 当前不建议

- 所有请求默认 GraphRAG；
- 所有知识迁移到独立图数据库；
- 用 Agent 自由决定检索策略且无 trace；
- 把自动摘要当作原始事实；
- 用单一 embedding 相似度替代全部检索。

## 15. 证据缺口

- “教学感知重排序”目前更多是 Askora 的设计推导，需要自建标注集与学习结果实验。
- GraphRAG 对个人学习长期保持/迁移的教育增益尚无充分直接证据。
- PageIndex 等开源工程的公开 benchmark 不能替代 Askora 自有长文档测试集。
- 需要构建同时标注“相关但不该暴露”和“相关且适合当前教学动作”的检索数据集。
