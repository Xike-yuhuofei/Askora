## 4. Independent Architecture Audit

### 4.1 Canonical teaching path

Repository architecture regressions assert：

- `DialogService` 不再写 `mastery_estimate`；
- production dialog 不再导入 direct Socratic path；
- production dialog 通过 `get_learning_orchestration_facade`；
- Orchestrator 不再写 `shared.mastery_vector` / `shared.mastery_confidence`；
- legacy engine mastery update 被显式拒绝。

结论：v0.2 主教学入口已收敛，未发现第二条默认 canonical teaching path。

### 4.2 Learner truth

E2E 以 `AssessmentResult → LearnerEvidence → WeightedBKTProjector → MasteryEstimate` 形成 canonical learner projection，并验证：

```text
independent weight > assisted weight > answer_exposed weight
answer_exposed weight = 0
```

固定 evidence + 固定 projector version 在重启后可得到相同 MasteryEstimate。

结论：未发现 Assessment/Orchestrator 直接把单次评分或模型输出作为 canonical mastery truth。

### 4.3 Review / Planner ownership

E2E 由 Review Scheduler 生成 ReviewSchedule，再由 Planner 消费 due 时点生成 `delayed_review` LearningActivity；重启后 schedule 与 plan 可恢复。

结论：v0.2 主闭环中 ReviewSchedule 与 LearningPlan 已分离。

### 4.4 Content / Retrieval boundary

E2E 验证 SourceSpan 可回放、EvidenceBundle learner-visible 过滤、grader-only 隔离以及 missing evidence 不允许模型补造资料事实。

结论：首条切片达到 source-grounded retrieval baseline。

### 4.5 Security / Trust

固定回归覆盖：

- document prompt injection；
- grader-only answer leakage；
- unsupported citation；
- unauthorized tool request；
- path traversal；
- server secret prompt/log leakage。

结论：v0.2 的关键 trust boundary 已形成自动化回归。

## 7. Known Legacy Debt

### LD-001 — `/users/profile` 仍直接读取 legacy `UserProfile`

路径：

```text
apps/backend/app/api/v1/users.py
apps/backend/tests/architecture/import_rules.py
```

现状：API 层仍直接 import/query `app.models.profile.UserProfile`；architecture allowlist 中该项的 `removal_exec` 仍写为 `EXEC-004`。

风险判断：当前路径为只读，没有发现其写 canonical MasteryEstimate，因此不构成 v0.2 第二事实源阻断；但它违反目标 `API → application/query boundary`，且可能展示 legacy mastery summary。

处理要求：在 v0.3 功能扩展前建立新的治理 EXEC，改为 canonical read model/query adapter，并删除该 allowlist。

### LD-002 — Legacy directory boundary 尚未完全物理迁移

`services/documents/`、`services/kt/`、`engines/` 等仍承担 compatibility adapter。v0.2 接受渐进迁移，不要求大爆炸重命名。

处理要求：后续只能单调减少 legacy cross-boundary responsibility，不得重新扩大状态所有权。

### LD-003 — CI verification evidence 未持久化

GitHub 当前 commit 没有可查询的 Actions/status check；仓库保存了测试代码和 real-model result，但没有持久化全量 `pytest / ruff / mypy / npm build` 的 CI run 证据。

风险判断：不改变当前代码语义，但属于发布治理缺口。

处理要求：v0.3 前优先建立最小 CI，至少固定 backend tests + ruff + frontend build；mypy 按当前基线逐步收敛。
