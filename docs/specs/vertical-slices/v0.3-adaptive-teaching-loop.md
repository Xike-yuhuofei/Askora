# Askora v0.3 Adaptive Teaching Loop Vertical Slice

> Spec ID 范围：`VSLICE-3xx`  
> 状态：Canonical Implementation Contract  
> 版本：v0.3  
> 上游：v0.3 Canonical Design、ADR-0001、ADR-0002、v0.3 Specs  
> 目标：在 v0.2 已冻结的真实学习闭环上，形成首个可 replay、可解释、可测试、可观测的 Adaptive Teaching Loop。
> 生命周期：已由 EXEC-007～013 实现并完成 release gate；本文件继续作为冻结实现合同保留。

## 1. Phase Position

v0.3 Vertical Slice 位于：

```text
Research Synthesis
→ Canonical Design Delta
→ Accepted ADR
→ Spec Delta
→ 【v0.3 Vertical Slice】
→ EXEC-007+
→ Implementation
→ v0.3 Release / Experiment Stage
```

本文件不是新的 Canonical Design，也不允许在实现中重新解释 ADR/Spec。若切片落地需要改变已冻结公共语义，必须停止并报告 `SPEC GAP`；用户已委托架构自治时，Codex MAY 先接受新的 ADR、更新 Spec 并冻结新的 EXEC，再依据新合同继续实现。

## 2. Slice Goal

v0.3 的最小成功不是“增加更多教学策略按钮”，而是证明以下链路在一个真实窄场景中闭合：

```text
exact learner / assessment / plan / review evidence
→ immutable TeachingContext
→ exact PolicyBundle
→ typed hard constraints
→ TeachingStage
→ legal candidate set
→ normalized deterministic scoring
→ anti-oscillation
→ stable tie-break
→ immutable TeachingAction + DecisionTrace
→ SYS02 / SYS08 tightening-only execution
→ SYS04 actual assistance + AssessmentResult
→ SYS03 evidence update
→ new material evidence
→ next SYS05 decision
→ later OutcomeObservation
```

Slice Done 必须同时满足 Engineering Correct 与 Policy Correct；若真实 human learning evidence 尚不足，必须诚实输出 `LEARNING_EVIDENCE_INSUFFICIENT`，不得把 OPVE、synthetic learner 或行为差异称为已证明学习效果。

## 3. Entry Baseline & Preconditions

v0.2 已冻结以下主链能力，本切片 MUST 复用，不得重建第二套：

- SourceDocument / SourceSpan；
- canonical learning facade / orchestrator；
- EvidenceBundle；
- deterministic AssessmentResult；
- LearnerEvidence → MasteryEstimate；
- ReviewSchedule → Planner；
- event/outbox/replay/recovery；
- real-model gateway baseline。

### VSLICE-300 — Legacy Read Boundary Must Be Closed First

v0.2 close-out 中 `GET /users/profile` 仍直接查询 legacy `UserProfile`。在 v0.3 adaptive state 扩展前 MUST：

- 建立 canonical read model / query adapter；
- API 不再直接 import/query legacy profile persistence model；
- legacy mastery/progress summary 只能作为明确标注的 compatibility projection；
- 删除对应 architecture allowlist debt 或建立新的、准确 retirement condition。

### VSLICE-301 — CI Evidence Must Be Durable

仓库已有 `.github/workflows/ci.yml`，但 v0.3 candidate commit/release MUST 有可查询、可持久化的 CI evidence。至少覆盖：

```text
backend tests
ruff / formatting / type baseline
migration check
frontend build
dependency audit
```

Real-model E2E MAY 使用受控手工/受保护 workflow，不得把 secret 写入仓库。

### VSLICE-302 — No New v0.3 Feature Before Preconditions

若 `VSLICE-300` 或 `VSLICE-301` 未完成，后续 adaptive policy implementation MAY 开发分支验证，但 MUST NOT 宣称 v0.3 Vertical Slice 已进入正式 implementation gate。

## 4. Primary End-to-End Scenario

首个切片只选 **一个主 KnowledgeUnit + 少量 prerequisite + deterministic assessment item family**。推荐使用 numeric / exact / multiple-choice 中一种可稳定自动判分的场景。

同一 fixture 必须能构造至少以下 evidence trajectory：

```text
A. insufficient / low-confidence evidence
   → EXPLICIT_INSTRUCTION or GUIDED_PRACTICE

B. assisted success
   → INDEPENDENT_VALIDATION_REQUIRED
   → no independent mastery promotion

C. fresh independent success
   → support may fade
   → FADING_PRACTICE / RETRIEVAL_PRACTICE becomes eligible

D. delayed independent retrieval
   → RETRIEVAL_PRACTICE evidence
   → ReviewSchedule / OutcomeObservation linkage

E. independent novel variant
   → TRANSFER_CHALLENGE

F. repeated failure or sufficiently supported misconception evidence
   → ERROR_REMEDIATION
```

六类 StrategyFamily MUST 都能由固定 scenario/OPVE fixture 覆盖，但单次真实用户 E2E 不要求强行经过全部六类。

### VSLICE-303 — Deterministic Time

Delayed retrieval / review 场景 MUST 通过注入或固定 `decision_time`、event time、fixture time 实现可重复测试；MUST NOT 依赖测试真实等待数小时/数天。

## 5. Slice Scope

本切片必须落地：

1. v0.3 public contract / schema migration；
2. six StrategyFamily + four-layer ontology；
3. immutable TeachingContext；
4. immutable/versioned PolicyBundle；
5. B3 constrained deterministic Teaching Policy；
6. typed hard constraints / soft preferences / experiment guardrails；
7. TeachingStage derivation；
8. deterministic candidate generation / feature / normalization / scoring / tie-break；
9. anti-oscillation；
10. orthogonal scaffold / hint / answer-exposure / assistance semantics；
11. ErrorType 7 + UNKNOWN；
12. independent validation obligation；
13. DecisionTrace v0.3 probability + replay；
14. legacy Socratic ownership cutover；
15. OutcomeObservation / TeachingEpisode / LearningTrajectory minimal data foundation；
16. optional ExperimentAssignment contract / assignment probability separation；
17. OPVE G0/G1/G2 harness；
18. engineering / policy / learning-evidence release status separation；
19. 9 migration candidate fixtures / compatibility behavior；
20. real-model execution within a fixed TeachingAction envelope。

## 6. Out of Scope

本切片 MUST NOT 引入：

- Contextual Bandit as canonical runtime；
- Offline / Online RL；
- DKT / Deep KT canonical learner truth；
- complex IRT-CAT；
- open-world misconception discovery；
- free-form LLM TeachingAction ownership；
- generic Productive Failure StrategyFamily；
- always-on Socratic tutor；
- executable policy DSL / embedded Python rules；
- autonomous multi-agent teaching controller；
- school-level population A/B infrastructure；
- synthetic learner 作为 human learning evidence；
- 为迁移目录而进行大爆炸重写。

B2 LLM selector 不是本切片完成条件；如保留，只能是同 hard shield / action vocabulary 下的 experiment baseline。

## 8. Phase A — v0.3 Contracts & Migration Cutover

### VSLICE-310

公共 contract MUST 首先支持：

```text
StrategyFamily
InteractionMove
ActionModifier
TeachingContext
TeachingStage
TeachingAction v0.3
PolicyBundle
orthogonal assistance snapshot
Assessment diagnosis 7+UNKNOWN
DecisionTrace v0.3
TeachingEpisode
LearningTrajectory
OutcomeObservation
ExperimentAssignment
```

### VSLICE-311 — Canonical Writer Cutover

v0.3 writer 启用后：

- old nine-family strategy enum MUST NOT canonical write；
- integer `scaffold_level` / `hint_level` / `answer_exposure_max` MUST NOT canonical write；
- old `experiment.propensity` MUST NOT 被无条件解释为 action propensity；
- old TeachingAction / policy config MAY read/audit only；
- legacy adapters MUST 有 retirement condition。

### VSLICE-312 — Nine Migration Candidates

必须为以下 9 类建立 migration / compatibility fixture：

1. historical strategy records；
2. historical TeachingAction；
3. old scaffold level；
4. old hint level；
5. old answer exposure scale；
6. legacy Socratic selector/state machine；
7. old policy config；
8. old DecisionTrace propensity；
9. historical replay。

Lossy / ambiguous mapping MUST 显式标记 `PARTIAL` / `UNKNOWN` / migration reason，MUST NOT 猜测。

### VSLICE-AC-A1

新写入数据只使用 v0.3 canonical schema；不存在 permanent dual-write。

### VSLICE-AC-A2

9 类 legacy fixture 均能给出 canonical target、compatibility behavior、ambiguity/replay status 与 retirement condition。

### VSLICE-AC-A3

旧历史缺失 exact version 时返回 `PARTIAL|NON_REPLAYABLE`，不得用当前 state/config 伪造 FULL replay。

## 9. Phase B — TeachingContext + PolicyBundle + Deterministic Policy Kernel

### VSLICE-320 — TeachingContext

每次 SYS05 decision MUST 从 exact SYS03/SYS04/SYS06/SYS07 refs 构造 immutable TeachingContext，并显式保存：

- decision time；
- schema version；
- context fingerprint；
- availability / missing / stale / low-confidence semantics；
- previous decision / assistance history；
- experiment assignment ref（如有）。

MUST NOT 将 TeachingContext 变成第二 LearnerState。

### VSLICE-321 — PolicyBundle

首个 production PolicyBundle MAY 是静态 typed configuration，但 MUST：

- immutable publish；
- exact version pin；
- content digest；
- atomic activation；
- historical retain；
- no executable/free-form runtime rule。

### VSLICE-322 — Policy Stack

B3 kernel MUST 实现：

```text
Hard Constraints
→ Stage Mapper
→ Candidate Table
→ Feature Builder
→ Normalization
→ Weighted Scoring
→ Anti-Oscillation
→ Stable Tie-break
→ Immutable TeachingAction
→ DecisionTrace
```

### VSLICE-323 — Hard Rule Coverage

`SYS05-241` 定义的 required hard-constraint families MUST 全部有 typed rule + stable reason code + G0 fixture。Hard-filtered action MUST 永不被 score、LLM、experiment 或 fallback 恢复。

### VSLICE-324 — Deterministic Probability

B3 DecisionTrace MUST：

```text
behavior_policy_type = DETERMINISTIC
action_propensity = null
```

Experiment assignment probability MUST 独立存储。

### VSLICE-AC-B1

相同 `TeachingContext + exact PolicyBundle + ExperimentAssignment` 产生相同 semantic TeachingAction。

### VSLICE-AC-B2

G0 中所有 hard rule `100% pass` 且 forbidden action = 0。

### VSLICE-AC-B3

TeachingStage 不写入 LearnerState truth；PolicyBundle activation 不重解释历史 action。

## 10. Phase C — Adaptive Transition, Anti-Oscillation & Validation

### VSLICE-330 — Material Evidence Gate

StrategyFamily / major action transition MUST 由 material evidence 支持，例如：new AssessmentResult、fresh independent Attempt、diagnostic probe、LearnerState update、explicit user request、prerequisite evidence、exposure event、meaningful review/delay transition。

单纯聊天轮数、重复 policy call、wording change、数秒 wall-clock 变化 MUST NOT 触发切换。

### VSLICE-331 — Anti-Oscillation

必须实现并 sequential replay：

```text
Material Evidence Gate
Sticky Continuity
Minimum Dwell by Evidence Opportunity
Hysteresis
Transition Priority
Repeated Failure Override
```

### VSLICE-332 — Independent Validation Obligation

`ASSISTED` 或 `ANSWER_EXPOSED` success MUST 创建 `INDEPENDENT_VALIDATION_REQUIRED`。只有 fresh independent Attempt/AssessmentResult 可提供满足事实。

MUST NOT 因：

- 已安排验证；
- 聊天继续；
- 时间经过；
- LLM 判断“应该会了”

而自动完成 obligation。

### VSLICE-333 — Error Remediation

SYS04 canonical ErrorType 只允许 7 类 + UNKNOWN。UNKNOWN / low diagnostic confidence MUST 支持 conservative probe / remediation path，不得强制猜测。

### VSLICE-AC-C1

无 material evidence 时重复 evaluation 不发生非法 strategy oscillation。

### VSLICE-AC-C2

Repeated failure 达到 versioned ceiling 后能合法退出 continuity、升级 support、重新诊断或 prerequisite remediation。

### VSLICE-AC-C3

Assisted / answer-exposed success 不会被视为已完成 independent validation。

## 11. Phase D — Cross-system Execution & Actual Assistance

### VSLICE-340 — SYS02 / SYS08 Tightening-only

SYS02 与 SYS08 MAY 收紧：

```text
scaffold_control
hint_specificity
answer_exposure
```

MUST NOT 扩大或自行改变 StrategyFamily / InteractionMove semantics。

### VSLICE-341 — Actual Experience Is Truth for Assessment

SYS04 Attempt MUST 记录实际经历：

```text
assistance_state
scaffold_control
hint_specificity
answer_exposure
```

不得用 SYS05 planned envelope 替代 actual experience。

### VSLICE-342 — Learner Evidence Eligibility

SYS03 MUST 基于 actual assistance snapshot 判断 eligibility/weight：

- ANSWER_EXPOSED success 不得成为 independent mastery evidence；
- ASSISTED 与 INDEPENDENT 必须有不同语义；
- assistance unknown 时 conservative，MUST NOT 默认 independent。

### VSLICE-343 — Legacy Socratic Boundary

legacy Socratic selector/state graph MAY 作为 bounded InteractionMove provider / execution adapter / fixture，但 MUST NOT final TeachingAction owner，也 MUST NOT override envelope。

### VSLICE-AC-D1

最终 rendered response 的实际 assistance/exposure 可追溯 TeachingAction、execution trace、Attempt 与 AssessmentResult。

### VSLICE-AC-D2

测试证明 SYS02/SYS08 不存在扩大 SYS05 envelope 的成功路径。

### VSLICE-AC-D3

legacy Socratic path 无 final TeachingAction ownership，ordinary/streaming 仍走 canonical orchestration path。

## 12. Phase E — Outcome, Experiment & Observability Foundation

### VSLICE-350 — OutcomeObservation

至少实现可记录：

```text
measurement_reference
independence / assistance
actual delay
transfer distance / novelty
score / success
measurement confidence
active learning time / time cost / hint cost
contamination status
attribution_scope
episode / trajectory refs
experiment association
```

### VSLICE-351 — Decision vs Outcome

DecisionTrace 只记录当时决策依据；OutcomeObservation 记录后来测到的结果。Outcome MUST NOT 回写历史 candidate scores / features / reasons。

### VSLICE-352 — Attribution

Delayed outcome MUST NOT 自动 last-touch 给最后一个 TeachingAction。只允许：

```text
ACTION_DIRECT
EPISODE_ASSOCIATED
TRAJECTORY_ASSOCIATED
EXPERIMENTALLY_CAUSAL
UNATTRIBUTABLE
```

没有实验识别条件时 MUST NOT 使用 `EXPERIMENTALLY_CAUSAL`。

### VSLICE-353 — ExperimentAssignment

默认非实验用户 flow MAY 没有 ExperimentAssignment。若启用 experiment fixture / future experiment，必须记录 assignment id/version/unit/variant/probability，并与 action propensity 分离。

### VSLICE-354 — Outcome Hierarchy

Primary learning outcomes 仅：

- no-hint independent success；
- delayed independent performance；
- independent transfer；
- unit-time capability gain。

Engagement、conversation turns、likes、hint count、tokens、session duration 只能是 process/experience diagnostics。

### VSLICE-AC-E1

任一 OutcomeObservation 可追到真实 measurement / actual assistance / time / episode refs。

### VSLICE-AC-E2

Delayed outcome 不会自动被归因给最后一个 action。

### VSLICE-AC-E3

assignment probability 与 action propensity 在 schema、trace、tests、metrics 中均不混用。

## 13. Phase F — OPVE, Recovery, Security & Release Gate

### VSLICE-360 — OPVE Six Layers

必须建立：

1. Contract Verification；
2. Scenario Replay；
3. Sequential Transition Replay；
4. Property / Metamorphic Tests；
5. Baseline Differential Replay；
6. Synthetic Learner Stress Test。

### VSLICE-361 — Gold Sets

必须支持：

```text
G0 Hard Constraint Gold
G1 Acceptable Action Set Gold
G2 Research / Calibration Set
```

G0 = 100%，forbidden action = 0；G1 使用 `selected_action ∈ acceptable_actions`，不得强制唯一 gold。

### VSLICE-362 — Replay / Recovery

必须验证：

- same context + bundle + assignment deterministic；
- event/policy replay 不调用在线 LLM；
- restart 恢复 pending workflow/outbox；
- migration/upcaster 可重跑且幂等；
- historical missing version 明确 PARTIAL/NON_REPLAYABLE；
- new PolicyBundle activation 不修改旧 decision semantics。

### VSLICE-363 — Security

必须覆盖：

- document/retrieval prompt injection；
- hard-rule override attempt；
- answer / grader leakage；
- SYS08/SYS02 envelope expansion attempt；
- unauthorized tool；
- sensitive prompt/log leakage；
- legacy Socratic override attempt。

### VSLICE-364 — Real-model E2E

至少一个 E2E MUST 使用实际配置模型完成：

```text
TeachingAction fixed
→ EvidenceBundle
→ model-generated explanation/hint/feedback within envelope
→ output validation
→ actual assistance event
→ deterministic AssessmentResult
→ next policy decision
```

模型 MAY 负责表达，MUST NOT 自由选择 TeachingAction。

### VSLICE-365 — Release Status

Release evaluation MUST 独立给出：

```text
Engineering Gate
Policy Correctness Gate
Learning Evidence Gate
```

若前两者 PASS、但尚无充分真实学习效果数据，最终状态 MUST 包含：

```text
LEARNING_EVIDENCE_INSUFFICIENT
```

这仍允许继续受控产品/实验迭代，但不得声称 adaptive policy 已证明优于 fixed strategy / free LLM tutor。

### VSLICE-AC-F1

OPVE 六层均有 fixture/test entry，G0/G1 gate 可自动判定。

### VSLICE-AC-F2

真实模型执行无法取得 TeachingAction ownership 或扩大 hard envelope。

### VSLICE-AC-F3

Engineering PASS / Policy PASS / Learning Evidence status 可独立判定与审计。

## 14. Definition of v0.3 Slice Done

以下全部满足才可称 v0.3 Adaptive Teaching Vertical Slice DONE：

1. v0.2 canonical learning loop 未被破坏，single-writer ownership 仍成立；
2. `/users/profile` legacy direct persistence read debt 已通过 canonical query/read-model boundary 收口；
3. candidate commit 有 durable CI evidence；
4. v0.3 canonical schemas 已成为唯一 active writer contract；
5. 9 migration candidates 有 executable fixtures 与 explicit replay status；
6. six StrategyFamily / four-layer ontology 在 runtime 与 tests 一致；
7. TeachingContext exact-version snapshot 可 replay；
8. PolicyBundle immutable/versioned/atomic activation；
9. hard constraints、stage、candidate、features、normalization、scoring、anti-oscillation、tie-break 均可单独测试；
10. G0 = 100%，forbidden action = 0；
11. G1 selected action 属 acceptable set；
12. repeated failure、independent success、low confidence、UNKNOWN diagnosis、direct answer 均有正确 transition behavior；
13. ASSISTED / ANSWER_EXPOSED 均建立 independent validation obligation；
14. SYS02 / SYS08 tightening-only；
15. SYS04 记录 actual assistance，SYS03 基于 actual facts 更新 evidence；
16. legacy Socratic 无 final TeachingAction ownership；
17. deterministic B3 `action_propensity=null`；
18. DecisionTrace 与 OutcomeObservation 分离；
19. Outcome / Experiment 不形成第九个 domain truth owner；
20. OPVE / replay / migration / recovery / security tests 通过；
21. 至少一个真实模型 E2E；
22. Engineering / Policy / Learning Evidence gate 状态诚实可审计；
23. 无 blocking `SPEC GAP`。

后续 Codex 实现 SHOULD 按依赖顺序拆为：

```text

          - /users/profile canonical read boundary
          - CI evidence gate

EXEC-008  v0.3 contracts + schema migration
          - ontology / TeachingContext / PolicyBundle
          - assistance / ErrorType / DecisionTrace

EXEC-009  deterministic teaching policy kernel
          - hard constraints / stage / candidates
          - feature / normalization / scoring / tie-break

EXEC-010  adaptive transition + anti-oscillation
          - material evidence gate
          - dwell / hysteresis / transition priority
          - validation obligation / remediation

EXEC-011  cross-system adaptive execution integration
          - SYS02/SYS08 tightening-only
          - actual assistance → SYS04 → SYS03

          - episode / trajectory / outcome
          - assignment probability separation
```
