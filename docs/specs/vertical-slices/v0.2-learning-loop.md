# Askora v0.2 First Vertical Learning Slice

> Spec ID：`VSLICE-*`  
> 状态：Canonical Implementation Contract  
> 版本：v0.2  
> 目标：形成首个“材料 → 教学 → 独立评估 → 掌握更新 → 复习”的真实可恢复闭环。

## 1. Scope

v0.2 首个垂直切片只要求：

```text
导入一份 PDF 或 Markdown
→ 建立 SourceDocument/SourceSpan
→ 用户确认一个可测量 LearningGoal
→ 生成一个 LearningActivity
→ 4.5 选择 TeachingAction
→ 4.2 构建 EvidenceBundle
→ 4.8 统一 Orchestrator 执行
→ 4.4 完成一个可确定性判分的 AssessmentAttempt
→ 4.3 接纳 LearnerEvidence 并更新 MasteryEstimate
→ 4.7 生成 ReviewSchedule
→ 4.6 将 due review 纳入后续计划
→ 重启后状态/任务可恢复
```

## 2. 固定约束

### VSLICE-001

单用户、单设备、本地优先；SQLite 必须可运行。

### VSLICE-002

首个场景只选择一个**可确定性评分**的知识/任务类型，避免在首条链路同时解决开放题 judge 可靠性。

### VSLICE-003

一次 LearningActivity 只设一个主 KnowledgeUnit，可附多个 prerequisite。

### VSLICE-004

普通、流式请求使用同一 canonical orchestrator/application facade。

### VSLICE-005

会话消息、engine shared context、LLM output 都不得成为 MasteryEstimate 的直接写入来源。

## 3. Out of Scope

本切片禁止：

- 微服务拆分；
- autonomous multi-agent；
- DKT/AKT 作为 canonical learner model；
- 强化学习；
- 通用大型知识图谱；
- LMS/学校多租户；
- 跨设备同步；
- 完整开放题自动评分体系；
- 复杂 CAT/IRT 校准；
- 为“架构漂亮”一次性重写全部 legacy code。

## 4. Target Architecture Slice

```text
API adapter
  ↓
Canonical Learning Facade / Orchestrator
  ├─ SYS06 current LearningActivity
  ├─ SYS05 TeachingAction
  ├─ SYS02 EvidenceBundle
  ├─ SYS08 engine/model execution
  ├─ SYS04 Attempt + deterministic AssessmentResult
  ├─ SYS03 LearnerEvidence + MasteryEstimate
  └─ SYS07 ReviewSchedule
        ↓
     SYS06 future plan input

All critical writes
  ↓
DB transaction + Outbox/LearningEvent
```

## 5. Phase A — Contracts & Durable Event Foundation

必须实现：

- 公共 Pydantic/domain contracts：LearningEventEnvelope v1、AssessmentResult、LearnerEvidence、MasteryEstimate、TeachingAction、EvidenceBundle、ReviewSchedule；
- event ledger + durable outbox/task；
- idempotency key；
- aggregate/version constraints；
- fixed-version replay skeleton；
- architecture tests 防止越权 imports/writes。

### VSLICE-AC-A1

同一 command 重复提交不产生第二份 event/evidence。

### VSLICE-AC-A2

状态写入与 outbox 原子提交。

### VSLICE-AC-A3

应用重启后 pending task 可继续或明确失败。

## 6. Phase B — Canonical Teaching Entry

当前真实代码已确认：

- `apps/backend/app/services/dialog/dialog_service.py` 非流式存在 direct Socratic 与 Orchestrator 双路径；
- 流式当前直接调用 `SocraticEngine.stream_response`；
- direct path 用 `EngineOutput.mastery_delta` 更新 `DialogSession.mastery_estimate`；
- Orchestrator path 也会从 `shared_ctx_snapshot.mastery_vector` 回写 `DialogSession.mastery_estimate`；
- `apps/backend/app/api/v1/orchestrator.py` 当前明确是 debug/demo endpoint。

目标：

### VSLICE-010

`DialogService.send_message` 与 `stream_message` MUST 统一调用 canonical learning facade/orchestrator。

### VSLICE-011

旧 Socratic direct path MAY 暂时保留为 adapter/test fixture，但 MUST 不再是默认生产教学入口。

### VSLICE-012

删除/停止所有基于 `EngineOutput.mastery_delta`、`SharedContext.mastery_vector` 对 canonical mastery 的直接写入。

### VSLICE-013

`DialogSession.mastery_estimate` 若为兼容 UI 暂留，只能是 SYS03 canonical MasteryEstimate 的只读 projection/cache，并明确删除条件；不得继续独立演进。

### VSLICE-AC-B1

普通与流式同一输入场景产生同一 TeachingAction/engine selection 业务链。

### VSLICE-AC-B2

代码测试证明 `DialogService/Orchestrator` 无法直接更新 learner mastery truth。

## 7. Phase C — Content & Retrieval

首期支持 PDF/Markdown：

```text
file
→ MaterialRevision/checksum
→ parse
→ SourceSpan
→ SourceChunk
→ minimal KnowledgeUnit binding
→ lexical+dense index
```

检索：

```text
TeachingAction evidence requirements
→ BM25 + dense
→ RRF
→ exposure/source filters
→ optional rerank
→ EvidenceBundle
→ citation validation
```

### VSLICE-AC-C1

任一 learner-visible citation 可定位原文件 revision + page/chapter/offset/span。

### VSLICE-AC-C2

answer exposure filter 在无提示 assessment 阶段能阻止完整答案进入 learner context。

### VSLICE-AC-C3

检索不到必要证据时返回 missing evidence，不让模型伪造资料事实。

## 8. Phase D — Assessment → Evidence → Learner Model

首期使用 deterministic item，例如：

- multiple choice；
- numeric/exact；
- 其他无需 LLM judge 的窄场景。

流程：

```text
AssessmentItem v1
→ Attempt + assistance snapshot
→ deterministic AssessmentResult
→ SYS03 evidence eligibility
→ LearnerEvidence
→ baseline mastery projection
→ MasteryEstimate vN
```

### VSLICE-020

必须稳定区分：

- independent correct；
- hinted correct；
- answer exposed；
- repeated item；
- invalid/unscorable。

### VSLICE-AC-D1

任一 MasteryEstimate 可追溯 item/version、Attempt、AssessmentResult、assistance 和 algorithm version。

### VSLICE-AC-D2

答案已暴露的正确回答不会直接提升为 stable mastery。

### VSLICE-AC-D3

固定 event/evidence 集合重放得到同一 mastery content。

## 9. Phase E — Review & Plan Integration

流程：

```text
valid retrieval evidence
→ SYS07 ReviewSchedule
→ next_due_at
→ due/overdue projection
→ SYS06 candidate activity
→ daily plan inclusion
```

### VSLICE-030

SYS07 只计算推荐 due；SYS06 决定实际计划，不得双写 next_due_at。

### VSLICE-AC-E1

ReviewSchedule 可追溯 source evidence/model version。

### VSLICE-AC-E2

重启后 due review 仍存在。

### VSLICE-AC-E3

Planner 纳入 review 不修改 memory state。

## 10. Phase F — Trust, Recovery & E2E

必须覆盖：

- document prompt injection；
- model timeout/fallback；
- structured output invalid；
- citation mismatch；
- answer leakage；
- outbox retry；
- app restart；
- event replay；
- schema migration；
- real model E2E。

### VSLICE-AC-F1

恶意材料不能覆盖 TeachingAction 或触发未授权工具。

### VSLICE-AC-F2

模型故障有明确降级，不产生 learner failure evidence。

### VSLICE-AC-F3

至少一个 E2E 调用真实已配置模型并完成材料→教学→评估链关键模型步骤。

## 11. Definition of Slice Done

以下全部满足才算 v0.2 首个垂直切片完成：

1. 共享学习状态变更由事件/证据推导，聊天文本不直接写 mastery；
2. hinted/answer-exposed/independent 结果可稳定区分；
3. mastery 可追溯题目、答题、评分、帮助状态和版本；
4. 文档/评估/复习后台任务重启可恢复；
5. 同事件日志+同投影版本重放状态一致；
6. 引用可定位原文件 revision 与具体 span；
7. Prompt Injection 不能改变系统策略/工具权限；
8. 普通与流式走同教学主链；
9. 模型超时/结构失败/供应商故障有显式降级；
10. E2E、migration、security、recovery tests 通过；
11. 至少一次真实模型 E2E；
12. 无已知未声明的 `SPEC GAP`。

## 12. Implementation Order

Codex MUST 按依赖顺序执行：

```text
EXEC-001 contracts + event/outbox foundation
→ EXEC-002 canonical teaching entry
→ EXEC-003 content + EvidenceBundle
→ EXEC-004 assessment + learner projection
→ EXEC-005 review + planner integration
→ EXEC-006 E2E/recovery/security gate
```

不得跳过前置合同直接在 legacy service 中继续堆功能。
