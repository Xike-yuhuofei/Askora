## 1. 文档现状摘要

目标文档第 4 章存在明显的成熟度断层：

- **4.1 内容解析与知识建模**：已达到较完整的领域设计与工程设计水平，包含分层内容模型、统一中间表示、证据锚点、知识对象与关系、置信度、质量门禁、增量更新、存储、事件、安全、当前仓库差距、分阶段路线与验收指标。
- **4.2 检索与知识供给**：已达到较完整的检索系统设计水平，明确了教学检索请求、多路召回、重排、GraphRAG/PageIndex 边界、`EvidenceBundle`、答案泄漏控制、引用、失败降级、评估与工程路线。
- **4.3～4.8**：主要停留在“问题定义 + 算法/能力清单”，缺少统一领域对象、状态所有权、输入输出契约、算法选择准则、失败降级、版本追踪、评价框架和分阶段实施方案。

因此第 4 章当前不是一套完整的八系统架构，而是“两套成熟子系统设计 + 六个待展开能力域”。

## 4. 已经详细设计的系统

### 4.1 内容解析与知识建模

必须保留的成熟内容包括：

- `RawAsset → MaterialRevision → DocumentNode → SourceSpan → KnowledgeObject → KnowledgeRelation → PedagogicalAsset → IndexProjection` 的分层思想；
- 关系数据库规范化模型作为事实源，向量库/全文索引/图数据库作为可重建投影；
- `DocumentIR`、稳定锚点、原文证据强绑定；
- 多粒度内容单元，避免一个固定 Chunk 同时承担检索、教学和引用；
- 知识对象、教学素材、知识关系分离；
- 硬前置关系证据要求、环检测与概念簇策略；
- 候选抽取、实体消歧、置信度、人工审核与发布门禁；
- 增量更新、版本追踪、事件、Outbox、解析安全；
- 当前仓库差距与 P0～P3 路线。

### 4.2 检索与知识供给

必须保留的成熟内容包括：

- “检索相关性 ≠ 教学适用性”的核心定位；
- 教学动作驱动的结构化检索需求；
- BM25 + Dense + Graph + Page/Hierarchy + 题库/误区等多路召回；
- RRF、Cross-Encoder、MMR、覆盖约束与上下文预算；
- `EvidenceBundle` 作为检索层唯一面向下游的知识供给协议；
- GraphRAG 与 PageIndex 的互补边界；
- 原文引用链与来源冲突处理；
- `L0～L4` 答案暴露等级与多阶段泄漏控制；
- 显式检索失败、降级和可观测轨迹；
- 传统检索指标 + 可信指标 + 教学专用指标 + 最终学习结果指标；
- MVP/第二阶段/第三阶段路线。

## 5. 职责冲突清单

### 5.1 学习者建模 vs 评估与错误诊断

当前冲突：

- 4.3 写“掌握概率、误区/迁移能力等状态”；
- 4.4 写“当前表现是否足以证明掌握、误区识别”。

建议冻结为：

- **4.4 只产生证据和评估结论**：题目判分、过程判分、错误类型、误区证据、AssessmentResult；
- **4.3 是学习者状态唯一拥有者**：把多个 AssessmentResult/行为事件与历史先验融合为 LearnerState、MasteryEstimate、Misconception hypothesis/state。

评估系统不能直接把“这题答对”写成“已掌握”。

### 5.2 教学策略选择 vs 学习路径与任务调度

当前冲突：

- 4.5 决定“当前应该讲解、提问、提示还是练习”；
- 4.6 决定“下一步学什么，今天学什么”。

建议冻结为：

- **4.6 拥有 LearningPlan 与任务集合/顺序的长期与中期决策权**；
- **4.5 拥有给定当前目标任务后 TeachingAction 的即时教学决策权**。

即：4.6 选“学哪个知识目标/任务”，4.5 选“怎么教当前任务”。

### 5.3 学习路径与任务调度 vs 记忆保持与复习调度

当前冲突：

- 4.6 已包含“遗忘风险排序”；
- 4.7 决定“什么时候复习”。

建议冻结为：

- **4.7 唯一负责产生/更新 ReviewSchedule 与复习到期优先级**；
- **4.6 只把到期复习任务作为计划约束/候选任务，与新学、迁移任务一起排入 LearningPlan**。

4.6 不重新计算遗忘曲线；4.7 不决定完整日计划。

### 5.4 检索与知识供给 vs 教学策略选择

4.2 已正确提出：“教学层决定需要什么，检索层决定从哪里取和取哪些”。需进一步冻结：

- 4.5 决定 `TeachingAction`、提示强度、答案暴露上限、证据需求；
- 4.2 只能在这些约束下规划查询、召回、重排和组成 EvidenceBundle；
- 4.2 不能因检索结果“看起来更好讲”而自行改变教学动作。

### 5.5 LLM/Agent vs 教学策略/计划/学习者状态

4.8 当前最容易形成“总控系统”。必须明确禁止：

- Agent 自行改变学习目标；
- LLM 自行决定掌握状态；
- LLM 直接修改 LearnerState、LearningPlan、ReviewSchedule；
- Agent 绕过 4.5 改变 TeachingAction；
- LLM 在检索失败时虚构证据。

4.8 的角色应是：**工作流执行、模型调用、工具编排、表达与可信控制**，而不是新的教学决策者。

### 5.6 4.2 引用校验 vs 4.8 输出校验

建议分层：

- 4.2 对 EvidenceBundle 内的来源锚点、证据完整性负责；
- 4.8 对最终生成内容是否忠实使用 EvidenceBundle、引用映射是否覆盖生成陈述负责。

两者分别是“证据有效性”和“生成忠实性”。

## 7. 术语和对象冲突清单

### 7.1 `KnowledgeObject` / `KnowledgeUnit` / `Concept`

现状：

- 4.1 使用 `KnowledgeObject` 作为可学习知识对象；
- 4.2 又定义 `KnowledgeUnit` 作为教学知识单元；
- 后续系统预期使用 `Concept`。

建议：

- `Concept` 作为领域语义的一种核心知识类型；
- `KnowledgeUnit` 作为可学习/可规划单元的统一对象；
- 4.1 原 `KnowledgeObject` 在集成时映射为统一 `KnowledgeUnit`，保留原有 `object_type` 等能力；
- `SourceChunk` 仅为原文检索/引用投影，不承担知识事实角色。

### 7.2 `PedagogicalAsset` 与 4.2 的知识单元类型

4.1 已定义 definition/example/exercise/hint/misconception 等 `PedagogicalAsset`，4.2 又将类似类型装进 `KnowledgeUnit.unit_type`。

建议：

- 知识事实/技能本体用 `KnowledgeUnit`；
- 教学载体用 `PedagogicalAsset` 或统一后的 `LearningActivity/AssessmentItem`；
- 检索层可返回二者，但不得重复存储同一语义。

### 7.3 `misconception`

现状：

- 4.1：材料/专家/模型假设层面的误区知识；
- 4.2：误区检索索引；
- 4.3：学习者当前误区状态；
- 4.4：本次作答中检测的误区。

建议区分：

- `Misconception`：规范误区定义；
- `AssessmentResult.misconception_evidence`：本次证据；
- `LearnerState.active_misconceptions`：学习者状态假设；
- 检索层只读取这些对象，不拥有它们。

### 7.4 “难度”

需区分：

- 内容固有难度；
- AssessmentItem 难度参数；
- 学习者能力参数；
- 对特定学习者的主观/预测难度。

不能把单一 `difficulty` 跨系统复用。

## 8. 重复领域对象与数据状态冲突

当前容易重复写入的状态：

1. **掌握度**：4.3、4.4、后文掌握门槛均可能写；应由 4.3 唯一持久化。
2. **误区状态**：4.1 的规范误区、4.4 的误区证据、4.3 的用户误区状态需分离。
3. **遗忘/记忆强度**：4.3 可作为学习者模型特征，但 4.7 才能拥有复习调度参数和下一次复习时间。
4. **学习阶段**：可由 4.3 提供状态估计，4.5 不应自行保存另一份阶段状态。
5. **教学动作**：4.5 决策后应产生不可变 TeachingAction/DecisionTrace，4.8 只执行。
6. **计划任务**：4.6 拥有计划；4.7 只提供到期复习候选与约束。
7. **原文事实 vs 系统生成解释**：4.1 已正确区分 provenance，后续必须沿用。

## 9. 输入输出缺失

4.3～4.8 尚缺统一输入输出契约。至少需要：

- 4.3：`LearningEvent / AssessmentResult / FeedbackSignal → LearnerState / MasteryEstimate`；
- 4.4：`AssessmentItem + Attempt + EvidenceBundle → AssessmentResult`；
- 4.5：`LearnerState + LearningObjective + AssessmentResult + TeachingContext → TeachingAction/TeachingStrategy`；
- 4.6：`LearningGoal + KnowledgeGraph + LearnerState + ReviewDueItems + TimeBudget → LearningPlan`；
- 4.7：`LearningEvent + MasteryEstimate + ReviewOutcome → ReviewSchedule`；
- 4.8：`TeachingAction + EvidenceBundle + workflow state → rendered interaction + ModelInference + execution events`。

## 10. 跨系统依赖缺失与隐含循环依赖

### 10.1 潜在循环：4.3 ↔ 4.4

评估结果更新学习者状态；学习者状态又可影响自适应评估题选择。解决方式：

- `4.4` 基于 LearnerState 的**只读快照**选择/评分；
- 输出 AssessmentResult 事件；
- `4.3` 异步/同步消费结果产生新 LearnerState 版本；
- 禁止在同一事务中互相直接修改对方状态。

### 10.2 潜在循环：4.5 ↔ 4.2

教学策略提出证据需求，检索结果又可能表明证据不足。解决方式：

- 4.2 返回 `missing_evidence/confidence`；
- 4.5 在下一次决策中读取该结果并选择降级动作；
- 4.2 不反向直接修改 TeachingAction。

### 10.3 潜在循环：4.6 ↔ 4.7

计划器使用复习到期任务；复习完成又改变后续调度。解决方式：

- 4.7 发布 ReviewSchedule/ReviewDue 事件；
- 4.6 将其作为规划输入；
- 执行结果经 LearningEvent 回到 4.7 更新下一次复习，不直接调用计划器改计划。

### 10.4 潜在循环：4.5 ↔ 4.8

Agent 执行失败可能需要策略降级。解决方式：

- 4.8 只产生执行失败/模型失败事件；
- 4.5 再次决策；
- Agent 不在内部自行替换成另一个教学策略。

## 11. 无法形成完整教学闭环的当前断点

当前第 4 章存在以下闭环断点：

1. `AssessmentResult → MasteryEstimate` 的正式更新规则缺失；
2. `LearnerState → TeachingAction` 的决策协议缺失；
3. `TeachingAction → TeachingRetrievalRequest` 的结构契约虽在 4.2 局部存在，但全章未统一；
4. `TeachingAction + EvidenceBundle → 可执行交互` 的 Agent 工作流缺失；
5. `LearningEvent → LearnerState/ReviewSchedule` 的事件投影关系缺失；
6. `ReviewSchedule → LearningPlan` 的合并机制缺失；
7. `LearningPlan → 当前 LearningObjective/Task` 的状态机缺失；
8. `延迟保持/迁移结果 → 稳定掌握` 的状态更新协议缺失；
9. 用户纠错如何回滚错误 LearnerState/误区假设缺失；
10. 所有核心算法尚未统一进入 DecisionTrace，无法可靠回放/A-B/离线评估。

## 12. 缺失能力清单

跨系统公共能力缺失：

- 统一领域对象与唯一创建/更新者；
- 统一事件 Envelope、幂等、顺序、重试、Outbox、DLQ；
- 统一 DecisionTrace；
- LLM 结构化输出与模型版本追踪；
- 统一权限/审计/用户纠正机制；
- 全链路实验分流与版本比较；
- 学习效果四级评价框架；
- 数据最小化与隐私边界；
- 算法降级和无模型模式；
- 反事实/离线策略评估基础设施。

后六系统独有能力将在阶段 D 展开。

## 13. 建议保留、合并、迁移和重写的内容

### 保留

- 4.1 的证据链、版本化、知识关系、质量门禁、事件、安全和工程路线；
- 4.2 的教学感知检索、EvidenceBundle、GraphRAG/PageIndex 边界、泄漏控制、引用、降级和评估；
- 原文第 6 章中“BKT + 题目难度 + 证据权重”“规则 + 状态机 + 加权评分优先于 RL”“事件溯源”等方向性结论，可迁移并吸收进新第 4 章。

### 合并

- 4.1 `KnowledgeObject` 与公共 `KnowledgeUnit` 语义；
- 4.2 的检索请求/证据对象与公共 `EvidenceBundle`；
- 各系统分散的日志、版本、LLM、重试、安全内容，合并为公共 AI 工程能力。

### 迁移

- 一般教学科学原理迁移到公共教学科学原则；
- 通用事件、Prompt、模型路由、缓存、可观测性、安全迁移到公共架构；
- 原文第 6 章中属于八系统算法内核的内容迁移进入对应系统，不在多个章节重复。

### 重写

- 4.3～4.8 全部从“能力清单”升级为完整领域/算法/工程设计；
- 全章重新定义唯一状态所有权与最终决策所有权；
- 建立统一闭环图和系统接口。

## 14. 下一阶段研究问题

阶段 B 必须优先回答：

1. 学术上如何区分“单次表现”“掌握”“长期保持”“迁移”？
2. BKT、IRT、PFA、DKT/SAKT 等在个人学习产品中的适用边界和数据要求是什么？
3. 形成性评价、反馈、Worked Examples、脚手架、Productive Failure 的证据强度与适用条件是什么？
4. FSRS/半衰期模型相对于 SM-2 的工程与证据优势是什么？
5. 教学策略中规则、启发式评分、监督学习、Bandit、Offline RL、在线受约束 RL 的正确演进顺序是什么？
6. 现代 RAG/GraphRAG/多阶段排序哪些技术是工程成熟，哪些尚不应成为 MVP 前提？
7. 如何将点击/时长等过程指标与独立完成、延迟保持、迁移等真正学习结果分离？
8. 如何对 LLM 教学系统建立 Prompt/模型/证据/决策的可追溯链？
9. 学习者模型错误时，如何允许用户纠正并安全重算状态？
10. 哪些行业产品能力有公开证据支持，哪些只能作为产品表层实践，不能推断其算法？

## 15. 阶段 A 结论

第 4 章的首要问题不是“缺少更多算法名词”，而是：

> **缺少统一状态所有权、决策所有权、领域对象和事件/决策协议，导致后六个系统尚不能与 4.1、4.2 组合成可回放、可验证、可演进的教学闭环。**

后续阶段必须以“唯一主责 + 事件解耦 + 证据驱动 + LLM 无业务真相所有权”为公共约束。
