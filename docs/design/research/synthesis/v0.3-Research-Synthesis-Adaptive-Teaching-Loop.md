## 1. Executive Summary

DR-03-01～04 形成的结论总体一致，没有要求推翻 Askora v0.2 已冻结的八系统边界或状态所有权。v0.3 真正需要做的是把当前 SYS05 的合同级 Teaching Policy 收敛为一个**可确定重放、可审计、可实验验证的 Adaptive Teaching Loop**，并把研究中新增的策略语义、诊断语义、支架语义、决策数据和学习效果验证要求送入下一阶段 Canonical Design Delta。

本综合冻结以下总模型：

```text
Fixed LearningObjective / LearningActivity
        ↓
Immutable TeachingContext Snapshot
        ↓
Typed Hard Constraints
        ↓
Derived TeachingStage
        ↓
Typed Candidate Generation / Decision Table
        ↓
Feature Builder
        ↓
Normalized Confidence-Aware Weighted Scoring
        ↓
Anti-Oscillation Gate
        ↓
Deterministic Tie-break
        ↓
Immutable TeachingAction
        ↓
DecisionTrace
        ↓
SYS02 EvidenceBundle + SYS08 constrained execution
        ↓
Attempt / AssessmentResult
        ↓
SYS03 LearnerState projection
        ↓
OutcomeObservation / delayed / transfer linkage
        ↓
SYS05 re-evaluation
```

v0.3 的 TeachingStrategy 顶层只保留六个真正影响 episode 控制语义的 family：

```text
EXPLICIT_INSTRUCTION
GUIDED_PRACTICE
FADING_PRACTICE
RETRIEVAL_PRACTICE
ERROR_REMEDIATION
TRANSFER_CHALLENGE
```

`DIRECT_INSTRUCTION`、`WORKED_EXAMPLE`、`SOCRATIC_PROBE`、`SELF_EXPLANATION_PROMPT` 等属于具体 `Interaction Move` / action variant；`METACOGNITIVE_REFLECTION` 默认降为 action modifier 或 SYS06 activity；`PRODUCTIVE_FAILURE` 不进入 v0.3 selectable baseline。

`TeachingStage` 不是第二套 LearnerState。它是 SYS05 在当前 `LearningActivity` 上根据带版本的 TeachingContext 临时派生的 policy feature；FSM/HSM 保存的是 stage/transition definition，而不是 learner truth。任何 cache 只能是可丢弃、可重建的 projection。

错误诊断冻结为：

```text
KNOWLEDGE_GAP
CONCEPTUAL_MISCONCEPTION
METHOD_SELECTION
EXECUTION
RETRIEVAL_FAILURE
TRANSFER_FAILURE
EXPRESSION_FORMAT
UNKNOWN
```

`UNKNOWN` 是合法、必要的诊断结果。SYS04 对单次 Attempt 负责 observed error / diagnostic evidence；SYS03 负责跨时间 misconception hypothesis；SYS05 只把诊断当作候选动作生成与评分信号。

v0.3 不采用 Bandit/RL。确定性 policy 下：

```text
behavior_policy_type = DETERMINISTIC
action_propensity = null
```

不得伪造 `1.0`。实验 variant 的 `assignment_probability` 与 action propensity 是两种完全不同的概率。

学习效果必须在帮助撤除后测量。四个核心 learning outcome family 冻结为：无提示独立成功、delayed independent performance、transfer、unit-time capability gain。engagement、conversation turns、likes、hint count 只能作为体验/过程诊断，不能成为主要学习目标。

v0.3 Release Gate 冻结为三层：

```text
Engineering Correct
+
Policy Correct
+
No Learning Harm
+
Directional Individual Learning Evidence
+
Correct Experimental Data Foundation
```

Learning Evidence Gate **不要求群体级统计显著性**，也不允许把 synthetic learner、expert agreement、scenario replay 冒充真实 learning efficacy。

## 2. Frozen Context

### 2.1 不重新讨论的 v0.2 冻结边界

```text
Knowledge truth / relations      → SYS01
EvidenceBundle                   → SYS02
LearnerState / MasteryEstimate   → SYS03
AssessmentResult                 → SYS04
TeachingAction                   → SYS05
LearningPlan / LearningActivity  → SYS06
ReviewSchedule / next_due_at     → SYS07
Model / tool / workflow execute  → SYS08
```

继续保持：

```text
AssessmentResult ≠ MasteryEstimate
LearningPlan ≠ TeachingAction
ReviewSchedule ≠ LearnerState
Misconception definition ≠ learner misconception hypothesis
ModelInference ≠ DecisionTrace
```

### 2.2 v0.3 研究目标

v0.3 只解决：

> 在 LearningActivity 已确定后，Askora 如何基于 learner evidence、assessment、error、assistance、review context 与用户约束，确定当前“怎么教”，并根据新证据增加、维持、减少或撤除支架。

### 2.3 三类结论必须区分

| 类型 | 含义 | 示例 |
|---|---|---|
| Scientific Evidence | 学习科学/ITS 对方向性原则有相对稳定支持 | novice 需要更多 guidance；独立提取与延迟测量重要 |
| Askora Engineering Choice | 为确定性、审计、测试、实验而做的系统约定 | 六个 strategy family；PolicyBundle；anti-oscillation stack |
| Hypothesis Requiring Experiment | 文献不能给出 Askora-specific 数值/最优选择 | failure ceiling、dwell、switch margin、hint sequence、weight |

所有经验阈值、权重、minimum dwell、failure ceiling、confidence cutoff、fade amount、delay window、transfer distance 必须配置化、版本化；不得包装成教育科学常数。

## 4. Unified Teaching Strategy Model

### 4.1 v0.3 最小 Strategy Family

冻结：

| Strategy Family | 核心 episode 目的 | 典型进入条件 |
|---|---|---|
| `EXPLICIT_INSTRUCTION` | 建立最低可操作表征、解释原则或完整建模 | novice、severe gap、复杂任务、用户明确要求解释 |
| `GUIDED_PRACTICE` | 在 learner-generated work 中提供有限支架 | 已有基本表征但独立能力不稳定 |
| `FADING_PRACTICE` | 从受支持表现向独立生成转移责任 | guided/worked example 后已有可信受支持成功 |
| `RETRIEVAL_PRACTICE` | 在低/无支架条件下形成与验证提取能力 | 已有最低可提取表征；immediate/delayed retrieval |
| `ERROR_REMEDIATION` | 针对足够可信的错误机制做局部或概念补救 | meaningful error/misconception/retrieval failure |
| `TRANSFER_CHALLENGE` | 验证并促进跨情境应用 | 已有可信 independent + retention evidence |

这是 Askora 的工程 ontology，不是声称文献天然存在六种策略。

### 4.2 当前 SYS05 九类如何统一

| 当前 SYS05 family | v0.3 统一结果 |
|---|---|
| `DIRECT_INSTRUCTION` | 降为 `EXPLICIT_INSTRUCTION` 下的 Interaction Move |
| `WORKED_EXAMPLE_FADING` | 拆分：`WORKED_EXAMPLE` move 属于 `EXPLICIT_INSTRUCTION`；fading episode 属于 `FADING_PRACTICE` |
| `SOCRATIC_PROBING` | 降为 `GUIDED_PRACTICE` / diagnostic context 下的 bounded Interaction Move |
| `GUIDED_PRACTICE` | 保留为 family |
| `ERROR_REMEDIATION` | 保留为 family |
| `RETRIEVAL_PRACTICE` | 保留为 family |
| `PRODUCTIVE_FAILURE` | v0.3 defer；不作为 selectable canonical family |
| `TRANSFER_CHALLENGE` | 保留为 family |
| `METACOGNITIVE_REFLECTION` | 默认 action modifier；若是阶段性复盘则复用 SYS06 `METACOGNITIVE_REVIEW` activity |

### 4.3 四层语义必须分开

```text
Strategy Family
    = 一个相对稳定教学 episode 的控制目的

TeachingAction
    = SYS05 产生的不可变、可执行、带版本的具体决策对象

Action Modifier
    = 不改变 family 的横切教学约束/增强语义
      例如 self-explanation、metacognitive check、feedback mode、transition intent

Interaction Move
    = action 内一次具体 tutor operation
      例如 explain、worked example、Socratic probe、hint、feedback、retrieval request、transfer task
```

推荐的 Interaction Move 候选包括：

```text
DIRECT_INSTRUCTION
WORKED_EXAMPLE
SOCRATIC_PROBE
ORIENTATION_HINT
CONCEPTUAL_HINT
SUBGOAL_HINT
PARTIAL_STEP
COMPLETION_PROBLEM
FADING_STEP
CORRECTNESS_FEEDBACK
PROCESS_FEEDBACK
RETRIEVAL_REQUEST
DELAYED_RETRIEVAL_REQUEST
TRANSFER_TASK
DIRECT_ANSWER_OVERRIDE
```

`SELF_EXPLANATION_PROMPT`、`METACOGNITIVE_CHECK` 可根据下一阶段设计决定是 modifier 还是 move，但不得再次升级为顶层 strategy family。

### 4.4 TeachingStage 最终语义

冻结：

> `TeachingStage` 是 SYS05 根据当前 `TeachingContext` 派生的 **activity-specific policy-control feature**，绝不是第二套 `LearnerState`。

建议正式命名 `DerivedTeachingStage`，避免与 SYS03 `LearnerState.learning_stage_summary` 混淆。

允许的逻辑 stage 可包含：

```text
DIAGNOSE
EXPLICIT_INSTRUCTION
GUIDED_PRACTICE
FADING_PRACTICE
RETRIEVAL_PRACTICE
DELAYED_RETRIEVAL
ERROR_REMEDIATION
TRANSFER_CHALLENGE
```

语义要求：

- **不 authoritative 持久化**为 learner truth；
- 当前值可由 canonical inputs + previous action history + exact policy version 重建；
- DecisionTrace 可记录本次 derived stage；
- 若实现需要 `EpisodeControlCache`，只能是 non-authoritative、可删除、可重建 projection；
- state machine 持久化/版本化的是 `stage definitions / entry guards / stay guards / exit guards / fallback transitions / transition priority`，不是 learner ability。

## 5. Unified TeachingContext

### 5.1 原则

`TeachingContext` 是一次 policy decision 的**不可变、带版本快照**。它不成为新的事实 owner，而只引用各 owner 的 exact version，并包含可重建的 derived features。

### 5.2 最小字段

| Field | Required? | Nature | Authoritative owner/source | Snapshot/version requirement |
|---|---|---|---|---|
| `learning_objective_ref` | MUST | authoritative ref | SYS06 | id + exact version |
| `learning_activity_ref` | MUST | authoritative ref | SYS06 | id + exact version |
| `activity_type / task_structure` | MUST | source/derived | SYS06 + SYS01 | source refs + feature schema version |
| `relative_complexity` | MAY | derived feature | SYS05 feature builder from task + learner evidence | feature value + availability + confidence + version |
| `mastery_estimate_ref` | MUST, value may be unavailable | authoritative ref | SYS03 | exact version or explicit missing/stale state |
| `mastery_confidence` | MUST when mastery available | authoritative field | SYS03 | inherited from estimate version |
| `prerequisite_state_refs` | MUST as collection, may be empty/unknown | authoritative refs | SYS03 over SYS01 prerequisite graph | exact learner/graph versions |
| `recent_assessment_result_ref` | MUST as nullable slot | authoritative ref | SYS04 | exact result version |
| `error_type` | MAY | authoritative current-attempt diagnosis | SYS04 | bound to AssessmentResult version |
| `diagnostic_confidence` | MAY | authoritative current diagnosis confidence | SYS04 | same result/diagnosis version |
| `diagnostic_evidence_refs` | MAY | authoritative evidence refs | SYS04 | stable refs |
| `active_misconception_hypothesis_refs` | MAY | authoritative long-term hypothesis | SYS03 | exact version |
| `assistance_history_summary` | MUST | derived summary over factual attempts | SYS04 attempt metadata; SYS05 builds projection | source attempt ids + summary version |
| `hint_history` | MAY | factual/derived | SYS04 Attempt | source attempt/event refs |
| `answer_exposure_history` | MUST | factual/derived | SYS04 Attempt | source refs; semantic exposure version |
| `independent_success_evidence` | MUST | authoritative accepted evidence refs/summary | SYS03 | evidence ids + learner-state version |
| `delayed_outcome_evidence` | MAY | authoritative accepted evidence/outcome refs | SYS03 + outcome records | ids + definition version |
| `transfer_evidence` | MAY | authoritative accepted evidence/outcome refs | SYS03 + SYS04 | ids + novelty/definition version |
| `review_context` | MUST as nullable slot | authoritative ref | SYS07 | ReviewSchedule/version or explicit none |
| `previous_teaching_action_ref` | MUST as nullable slot | authoritative ref | SYS05 | exact action id/version |
| `previous_action_outcome_refs` | MAY | linked observations | SYS04/SYS08/outcome ledger | stable refs |
| `user_request_constraints` | MUST | user fact / request fact | current request/session contract | immutable structured snapshot |
| `time_budget` | MAY | user/planner constraint | request/SYS06 | exact value + source |
| `accessibility_constraints` | MAY | user constraint | user/session profile | immutable snapshot/reference |
| `decision_time` | MUST | snapshot fact | policy request | explicit timestamp; policy code不得直接调用 wall clock |
| `context_schema_version` | MUST | schema metadata | SYS05 contract | immutable |
| `context_fingerprint` | SHOULD | replay/audit metadata | SYS05 | deterministic digest |

### 5.3 Derived features

所有 derived feature 必须采用：

```text
value
availability
confidence
feature_schema_version
```

不得将 missing 当作 `0`。安全相关字段缺失时走 conservative/hard fallback；普通 soft feature 缺失时 neutral contribution + explicit uncertainty，不重新放大剩余权重。

### 5.4 TeachingContext 不负责

- 不复制完整 LearnerState 形成第二事实源；
- 不写 mastery；
- 不改变 AssessmentResult；
- 不重排 LearningPlan；
- 不保存自由 LLM 推理；
- 不以运行时 `now()`、隐式 prompt memory 或未版本化配置影响 replay。

## 6. Unified Error / Remediation Model

### 6.1 v0.3 Error Taxonomy

冻结：

```text
KNOWLEDGE_GAP
CONCEPTUAL_MISCONCEPTION
METHOD_SELECTION
EXECUTION
RETRIEVAL_FAILURE
TRANSFER_FAILURE
EXPRESSION_FORMAT
UNKNOWN
```

### 6.2 与当前 Domain Model 的差异

当前 enum：

```text
knowledge_gap
misconception
condition_omission
method_selection
execution
retrieval_failure
transfer_failure
expression_incomplete
metacognitive
unknown
```

综合结论：

- `condition_omission` → 降为 `reason_code` 或 `EXECUTION/METHOD_SELECTION` 下的诊断细节；**Canonical/Spec Delta required**。
- `metacognitive` → 不作为核心 error type；转为 TeachingContext behavioral signal / reason code / reflection modifier；**Canonical/Spec Delta required**。
- `expression_incomplete` → 泛化为 `EXPRESSION_FORMAT`；**Canonical/Spec Delta required**。
- `attention/careless` → v0.3 不新增；证据不足时 `UNKNOWN`，局部 slip 可 `EXECUTION + POSSIBLE_SLIP`。

### 6.3 Diagnostic confidence 必须独立

```text
assessment_confidence
≠
diagnostic_confidence
```

前者回答“判分是否可靠”；后者回答“为什么出现该表现的解释是否可靠”。

推荐 SYS04 diagnosis 最小结构：

```text
error_type
diagnostic_confidence
diagnostic_evidence_refs
alternative_hypotheses
reason_codes
needs_probe
```

### 6.4 Misconception 三层语义

```text
Observed Error                 → SYS04
Misconception Evidence        → SYS04
Persistent Misconception Hypothesis → SYS03
```

SYS04 不得把单次错误写成长期 hypothesis；SYS05 不得拥有 diagnosis truth。

### 6.5 Remediation 只生成候选

| Error | 典型 candidate remediation | 必须避免 |
|---|---|---|
| `KNOWLEDGE_GAP` | prerequisite remediation、explanation、worked example、guided practice | 机械重复高难独立题 |
| `CONCEPTUAL_MISCONCEPTION` | alternative representation、counterexample、conceptual explanation、guided practice | 只报答案或贴永久标签 |
| `METHOD_SELECTION` | strategy comparison、适用条件辨析、worked-example comparison | 整章重教 |
| `EXECUTION` | local corrective feedback、从最后正确步骤重试 | 全面概念重教 |
| `RETRIEVAL_FAILURE` | minimal cue、retrieval、cue fading、delayed retrieval | 默认长篇重讲/立即完整答案 |
| `TRANSFER_FAILURE` | analogical mapping、near→far transfer、guided mapping | 一次失败推翻基础 mastery |
| `EXPRESSION_FORMAT` | format/representation correction、self-correction | 概念重教 |
| `UNKNOWN` | diagnostic probe、common-safe low-exposure guidance | 高承诺个性化 remediation |

最终 action 始终由 SYS05 选择。

### 6.6 Probe 触发条件

当且仅当以下同时成立时提高 diagnostic probe 候选优先级：

```text
>= 2 plausible hypotheses
AND hypotheses lead to meaningfully different remediation
AND current evidence cannot distinguish them reliably
AND probe cost is reasonable
```

具体 confidence cutoff 仍是 versioned configurable parameter。

## 7. Unified Policy Decision Architecture

### 7.1 冻结架构

```text
TeachingContext Snapshot
→ Typed Hard Constraints
→ Derived Teaching Stage
→ Candidate Generation / Decision Table
→ Feature Builder
→ Normalized Weighted Scoring
→ Anti-Oscillation Gate
→ Deterministic Tie-break
→ Immutable TeachingAction
→ DecisionTrace
```

### 7.2 每层职责

| Layer | Input | Output | 负责 | 不负责 |
|---|---|---|---|---|
| TeachingContext Snapshot | owner objects/versions | immutable context | 固定决策输入、missing semantics、fingerprint | 不成为事实 owner |
| Typed Hard Constraints | context + policy bundle | admissibility envelope | 过滤绝对不允许动作、产生 reason codes | 不比较教学偏好优劣 |
| Derived Teaching Stage | context + transition definitions | transient stage + obligations | 解释当前 activity 的控制阶段 | 不保存 learner truth |
| Candidate Generation | stage + error + activity + obligations | typed action templates | 用有限 decision table 产生可行候选 | 不执行任意 DSL，不最终排序 |
| Feature Builder | context + candidates | normalized features + confidence | 构造 stable semantic features | 不用 LLM 自报 confidence |
| Weighted Scoring | eligible candidates + features + versioned weights | base scores | 比较 soft trade-off | 不复活被 hard filter 的动作，不声称 causal learning gain |
| Anti-Oscillation Gate | scores + previous action + new evidence | stay/switch adjusted candidates | material evidence、dwell、hysteresis、transition cost | 不替代 hard exit |
| Deterministic Tie-break | adjusted candidates | selected candidate | 固定稳定排序 | 不随机探索 |
| Immutable TeachingAction | selected candidate + exact versions | executable action | 冻结 family/move/scaffold/exposure/conditions | SYS08 不可改语义 |
| DecisionTrace | 全部决策摘要 | append-only audit payload | replay、解释、shadow compare | 不成为业务状态 owner |

### 7.3 Scoring 语义

推荐：

```text
score(action) =
  + learning_value_proxy
  + diagnostic_value
  + stage_fit
  + remediation_fit
  + review_fit
  - hint_dependency_risk
  - cognitive_load_penalty
  - time_cost
  - transition_cost
  - oscillation_penalty
```

其中 `learning_value_proxy` 只是 heuristic feature，不是因果学习增益预测。

Normalization 必须由 `feature_schema_version + normalization_version` 冻结，不得针对当前候选集合动态 min/max normalization。

### 7.4 PolicyBundle

下一阶段建议形成不可变：

```text
PolicyBundleManifest
schema_version
policy_version
hard_rule_set_version
stage_mapper_version
candidate_table_version
feature_schema_version
normalization_version
weight_profile_version
anti_oscillation_profile_version
tie_break_version
fallback_profile_version
subject_profile_version
content_digest
```

配置只允许：threshold、weight、enum、mapping、priority、action ID、feature ID、reason-code ID；不得演化为 arbitrary expression / script / embedded Python / LLM-generated condition。

### 7.5 Determinism / replay

固定：

```text
TeachingContext snapshot
+ PolicyBundle version/digest
+ TeachingStrategy definition version
+ experiment assignment
```

必须得到相同 semantic TeachingAction。

政策 evaluator：

- 不直接读取 mutable state；
- 不直接 `now()`；
- canonical replay 不调用 online LLM；
- config hot reload 只影响新 decision；
- historical config 缺失必须标记 replayability gap；
- deterministic baseline 不需要 random seed。

## 8. Scaffold / Hint / Exposure Semantics

### 8.1 四者独立但相关

冻结：

| Concept | 语义 | 决策 owner | 事实记录 owner | SYS03 是否消费 |
|---|---|---|---|---|
| `scaffold level/control` | 系统承担多少 task decomposition / cognitive control | SYS05 | SYS04 Attempt 记录实际经历；SYS05 trace 记录决定值 | 可作辅助 evidence feature，但不单独决定 mastery |
| `hint level/specificity` | 提示具体到什么程度 | SYS05 冻结 ceiling/target | SYS04 记录 actual/max hint | 是，影响 evidence weight / hint dependency |
| `answer exposure` | 是否暴露任务特定关键步骤/正确答案 | SYS05 冻结上限；SYS02/SYS08 只能收紧不能放宽 | SYS04 记录 actual exposure | **必须**，直接影响 evidence eligibility/weight |
| `assistance state` | 当前 Attempt 的测量分类：independent / assisted / answer-exposed | 由 SYS04 根据实际经历确定 | SYS04 | **必须** |

### 8.2 推荐正交字段

下一阶段设计优先采用：

```text
scaffold_control: NONE | LOW | MEDIUM | HIGH
hint_specificity: NONE | ORIENTATION | CONCEPTUAL_STRATEGIC | SUBGOAL | PARTIAL_STEP | BOTTOM_OUT
answer_exposure: NONE | PARTIAL | COMPLETE
delivery_mode: ON_REQUEST | OFFERED | SYSTEM_TRIGGERED
assistance_state: INDEPENDENT | ASSISTED | ANSWER_EXPOSED
support_reason: reason codes
transition_intent: INCREASE | MAINTAIN | FADE | REMOVE | VERIFY
```

现行单一整数 `scaffold_level/hint_level` 可继续作为迁移期字段，但不能同时承载 support、specificity 与 exposure 语义。

### 8.3 Assisted success → independent validation debt

冻结：

> Assisted success 证明“在该 support 条件下可完成”，不证明 clean independent capability。

SYS05 必须从 assistance history 派生：

```text
independent_validation_required = true
```

这是 **policy obligation / derived debt**，不是第二套 mastery state。债务通过新的无帮助、未污染 assessment opportunity 消除。

### 8.4 Answer-exposed success

冻结：

- 当前 Attempt 必须为 `ANSWER_EXPOSED`；
- 不得晋升 stable mastery；
- 当前 frozen baseline 下 answer-exposed success 对 stable mastery 的高权贡献为 0；
- 后续必须安排 fresh item / fresh context 的 no-hint independent validation；
- 延迟/迁移 outcome 若期间存在重新暴露，必须标记 contamination，而不是假装 clean retention。

### 8.5 User asks direct answer

用户直接答案请求本身属于**高优先级 soft preference/user autonomy input**，不是允许绕过 hard constraints 的通行证。

- 非正式教学且不存在 assessment integrity 冲突：允许 direct explanation / answer-bearing move 候选显著提高优先级；
- 当前正在进行 no-hint independent assessment：必须先结束、取消或重分类该 assessment，之后才能暴露答案；
- 一旦提供答案，记录 actual exposure，并产生 independent-validation obligation。

## 9. DecisionTrace & Future-Learning Data Contract

### 9.1 当前必须可审计的数据

SYS05 DecisionTrace 至少应覆盖：

```text
decision_id
context refs/version + context_fingerprint
policy_bundle_version/hash
strategy/version
derived_policy_stage + stage_mapper_version
available_action_set
hard_filtered_actions + reason_codes

base/raw score
normalized/final score
selected_action
previous_action_id
transition_reason
material_evidence_refs
tie_break_rule/reason
experiment assignment
behavior_policy_type
replayability status
```

### 9.2 Outcome 不应回写修改旧 DecisionTrace

以下数据**当前必须记录并可通过 `decision_id/action_id` 关联**，但采用 append-only `OutcomeObservation` / episode records，而不是持续膨胀旧 DecisionTrace：

```text
short-term outcome
next independent outcome
delayed retention outcome
transfer outcome
assistance consumption
answer exposure
time cost
hint cost
measurement confidence
actual delay
novelty / transfer distance
censoring / contamination reason
```

即：

> 必须有 outcome links，不要求把所有 outcome physically inline 到 immutable DecisionTrace。

### 9.3 Propensity

冻结：

```text
behavior_policy_type = DETERMINISTIC
action_propensity = null
propensity_status = NOT_APPLICABLE_NO_RANDOMIZATION
```

不得把数学上的 deterministic probability `1.0` 写入并让分析系统误判为 OPE-ready。

### 9.4 Experiment assignment probability ≠ action propensity

```text
variant_assignment_probability
≠
action_selection_probability
```

B2/B3 若 50/50 随机：`assignment_probability = 0.5`；B3 内部仍是 deterministic，因此 `action_propensity = null`。

只有未来在 hard-filtered safe action set 上真正按已知分布随机选择 action 时，才记录 action propensity，且必须在 decision time 写入，不能事后猜测。

### 9.5 Episode / trajectory / attribution

建议下一阶段正式化：

```text
TeachingEpisode
LearningTrajectory
OutcomeObservation
```

Attribution scope 至少区分：

```text
ACTION_DIRECT
EPISODE_ASSOCIATED
TRAJECTORY_ASSOCIATED
EXPERIMENTALLY_CAUSAL
UNATTRIBUTABLE
```

Delayed outcome 默认不做 last-touch action attribution。

## 10. Outcome & Evaluation Framework

### 10.1 Outcome Hierarchy

#### Primary Learning Outcomes

冻结为四个 family：

1. **No-hint independent success / independent capability**；
2. **Delayed independent performance / retention**；
3. **Independent transfer**：near 与 far 分开记录；
4. **Unit-time capability gain / learning efficiency**。

每个具体实验必须预注册/预声明一个 primary outcome，避免 post-hoc 指标选择。

#### Secondary Learning Outcomes

- next fresh-item independent success；
- immediate independent post-test；
- 24–72h delayed outcome；
- repeated independent success；
- misconception recurrence；
- time to stable mastery；
- relearning speed；
- longer-delay retention（可选）。

#### Process Diagnostics

- hint requests/count/level；
- scaffold level / fading rate；
- answer exposure；
- strategy switches；
- repeated failure count；
- Socratic turns；
- worked-example exposure；
- response latency；
- fallback；
- user override；
- hint dependency。

这些用于解释过程，**不能作为 learning efficacy 的主要证据**。

#### Safety / Trust Guardrails

- hard constraint violation；
- answer leakage / assessment contamination；
- model override；
- unsupported citation / fabricated attribution；
- grader disagreement / invalid assessment；
- system failure misclassified as learner failure；
- false mastery promotion；
- experiment opt-out violation。

### 10.2 明确禁止的主要 learning objective

```text
engagement
conversation turns
likes
token count
hint count
session duration
```

它们可以是 UX、成本、过程 telemetry，但不能成为 Teaching Policy 的主要 reward / learning objective。

### 10.3 Offline Policy Verification & Evaluation（OPVE）

v0.3 不具备 RL/OPE 所需的 action overlap、真实 propensity 和长期稳定 reward，因此正式名称应是 OPVE，而不是因果 Offline Policy Evaluation。

层级冻结：

```text
OPVE-0 Contract Verification
→ OPVE-1 Scenario Replay
→ OPVE-2 Sequential Transition Replay
→ OPVE-3 Property / Metamorphic Tests
→ OPVE-4 Baseline Differential Replay
→ OPVE-5 Synthetic Learner Stress Test
```

### 10.4 Gold Set

三层：

```text
G0 Constraint Gold
G1 Pedagogical Acceptability Gold
G2 Research / Calibration Set
```

- G0：无自由裁量，必须 100% 通过；
- G1：允许多个 acceptable action，不强造唯一 gold；
- G2：用于权重/阈值/策略假设校准，不作为 blocking gate。

### 10.5 OPVE 可以证明什么

可以严格证明：

- deterministic replay；
- hard constraint compliance；
- forbidden action never selected；
- answer leakage regression；
- trace completeness；
- transition correctness；
- infinite loop / oscillation / unreachable state 等结构问题。

不能证明：

- 人类真的学得更好；
- B3 比 B2 有真实 learning advantage；
- mastery threshold 有心理学真实性；
- synthetic learner 的“提升”可外推给人类。

### 10.6 Real-user N-of-1

主比较冻结：

```text
B2 = LLM chooses TeachingAction under same hard shield
vs
B3 = Askora deterministic Adaptive Teaching Policy
```

必须保持相同：

- TeachingContext；
- action vocabulary；
- model snapshot；
- retrieval；
- assessment stack；
- generation pipeline；
- hard policy shield；
- outcome definitions。

实验采用 **matched-content randomized/counterbalanced N-of-1**，而不是对同一知识点做可逆 ABAB。学习不可 wash out。

核心测量：

```text
Pretest
→ Teaching Episode
→ Immediate no-hint independent check
→ Delayed independent check
→ Near transfer
→ Optional far transfer
```

样本对数、delay window、practical harm margin 等属于预声明、版本化实验参数，不是科学常数。

### 10.7 N-of-1 能证明什么

在随机 matched episodes、测量完整、污染受控的条件下，可以形成：

> 对当前用户、当前内容分布、当前时间和实现版本，B3 相对 B2 的个体层方向性或因果证据。

不能外推为 population efficacy，也不能证明对所有学科、所有人有效。

## 11. v0.3 Release Gate

v0.3 冻结三个 blocking gate，但三者含义分离。

### 11.1 Engineering Gate

必须满足：

- fixed context + policy version + assignment → 100% semantic replay；
- TeachingAction trace 完整；
- SYS08/LLM 无法改变 action semantics、scaffold/exposure ceiling；
- no-hint assessment regression 中 answer leakage = 0；
- hard constraint violation = 0；
- model/sandbox/retrieval failure 不形成 learner failure evidence；
- 适用 TEST L0–L6、recovery/idempotency/versioning 要求通过。

### 11.2 Policy Correctness Gate

必须满足：

- G0 Constraint Gold = 100% pass；
- G1 `selected_action ∈ acceptable_actions`；
- forbidden action selected = 0；
- 至少覆盖 novice、prerequisite gap、repeated failure、misconception、assisted success、independent success、delayed success、transfer、direct-answer request、low confidence、no-hint assessment、answer-exposed success；
- sequence replay 证明：

```text
repeated failure → exit/escalation
independent evidence → fading
answer exposure → independent-validation obligation
```

- synthetic long-run stress 无无限 loop、非法 transition、无界 oscillation。

### 11.3 Learning Evidence Gate

**不要求大规模统计显著性。**

必须形成：

```text
Engineering Correct
+
Policy Correct
+
No Learning Harm
+
Directional Individual Learning Evidence
+
Correct Experimental Data Foundation
```

最低要求：

- B2/B3 real-user matched comparison 使用相同 assessment/model/retrieval/hard shield；
- 收集 clean immediate independent、delayed independent、near transfer、active learning time；
- delayed-independent 不出现预声明 practical harm margin 之外的 material negative direction；
- 至少一个 primary learning outcome family 出现跨 matched episodes 的一致有利方向；
- answer exposure、false mastery、safety/trust guardrail 不恶化；
- raw pair-level outcomes 可审计；
- 不把单用户结果描述为 population efficacy；
- delayed/transfer outcome 大量缺失时返回 `LEARNING_EVIDENCE_INSUFFICIENT`，不得推断有效。

Engineering + Policy 通过但 Learning Evidence 不充分时，结论应是：

> policy implementation correct; learning benefit not yet demonstrated.

正确动作是继续迭代 deterministic policy，而不是升级到更复杂算法。
