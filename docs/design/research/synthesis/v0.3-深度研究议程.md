## 1. 研究目标

本轮 Deep Research 只回答一个中心问题：

> 如何把 Askora 已冻结的 SYS05 Teaching Policy baseline 转化为具有教育科学依据、可实现、可审计、可验证的 Adaptive Teaching Loop？

研究结果不直接成为实现规范。知识形成链保持：

```text
Deep Research Evidence
→ Synthesis
→ Canonical Design v0.3 Delta
→ ADR（如需要）
→ Spec Delta
→ v0.3 Vertical Slice
→ EXEC-007+
→ Codex
```

## 2. 不需要重新研究的内容

以下已冻结，不属于本轮研究问题：

- 八类技术系统是否应重新划分；
- 状态所有权；
- AssessmentResult / MasteryEstimate 分离；
- LearningPlan / TeachingAction 分离；
- ReviewSchedule / LearnerState 分离；
- EvidenceBundle ownership；
- LLM/Agent 不拥有业务真相；
- v0.3 是否直接采用 RL、多 Agent、Deep KT；
- 模块化单体是否应改微服务。

若外部资料提出不同架构，只作为对比证据，不自动推翻 Askora 已冻结边界。

## 3. Research Delta 总览

建议执行 **4 个专项 Deep Research**，而不是 8 次分系统重研。

| ID | 专项 | 要解决的设计不确定性 | 主要影响 |
|---|---|---|---|
| DR-03-01 | 教学策略与支架转换 | 什么状态下应该讲、问、提示、练、撤支架、迁移 | SYS05 |

| DR-03-04 | 学习效果验证与产品实验 | 如何证明策略真的改善独立成功、延迟保持、迁移 | Quality / Analytics / UX |

四项可独立研究，但最终必须统一综合，禁止各自产生冲突的 TeachingAction 语义。

# DR-03-01 教学策略与支架转换

## 核心问题

在以下输入下：

```text
LearningActivity
LearnerState / confidence
prerequisite gap
recent AssessmentResult
error type
hint / answer exposure history
independent success history
review / delay context
user request
```

应该如何选择：

```text
DIRECT_INSTRUCTION
WORKED_EXAMPLE
SOCRATIC_PROBING
GUIDED_PRACTICE
RETRIEVAL_PRACTICE
ERROR_REMEDIATION
TRANSFER_CHALLENGE
```

以及何时升级/降低 scaffold？

## 必须研究的证据主题

- worked-example effect 与 expertise reversal；
- cognitive load / element interactivity；
- scaffolding、fading、contingent tutoring；
- retrieval practice；
- self-explanation；
- Socratic/dialogic tutoring 的适用边界；
- productive failure 的适用条件与风险；
- feedback timing / elaborated feedback；
- mastery learning 与 deliberate practice；
- novice / intermediate / advanced learner 的策略差异；
- ITS 中 step-based tutoring、hint sequence、knowledge component mastery 的实践；
- 近年 LLM Tutor 是否有可靠证据证明特定对话策略优于自由聊天。

## 必须输出

1. `TeachingStrategy Evidence Matrix`：策略 × 学习状态 × 内容/任务条件 × 证据强度；
2. `Transition Condition Matrix`：何时进入、保持、升级、降级、退出；
3. hard constraints 与 soft preference 的边界；
4. scaffold level / hint level 的建议定义；
5. 用户明确要求直接答案时如何兼容学习目标与自主权；
6. 明确哪些阈值有证据、哪些只能先设可调参数；
7. v0.3 推荐最小策略族与明确拒绝项。

## 禁止输出

- 不直接写 Python 状态机；
- 不直接生成 EXEC；
- 不把“某论文平均效果量”直接转成用户 mastery 阈值；
- 不以单一教育理论作为全学科统一策略。

# DR-03-02 错误诊断到教学补救

## 核心问题

Askora 需要什么**最小、可靠、可操作**的 error/misconception taxonomy，才能支持 SYS05 做不同 remediation，而不是追求无限细粒度诊断？

## 重点比较

至少区分并验证：

- prerequisite / knowledge gap；
- conceptual misconception；
- strategy / method selection error；
- execution / procedural slip；
- retrieval failure；
- transfer failure；
- answer-format / expression error；
- uncertainty / insufficient evidence。

研究：

- 哪些类型可以由 deterministic rule / task trace 判断；
- 哪些需要 diagnostic probe；
- 哪些可由 rubric-constrained LLM 给出候选；
- LLM misconception diagnosis 的可靠性、偏差与 calibration；
- 单次错误何时只记 evidence，何时足以激活 misconception hypothesis；
- remediation mapping：补前置、换表征、worked example、提示、重新提取、变式、迁移等。

## 必须输出

1. v0.3 最小 error taxonomy；
2. 每类错误的 required evidence；
3. assessment confidence / diagnostic confidence 处理；
4. `error → candidate remediation` 映射，但最终 TeachingAction 仍归 SYS05；
5. 需要追加 diagnostic probe 的条件；
6. LLM 可以做什么、禁止做什么；
7. 可建立自动化 gold set 的测试案例设计。

# DR-03-03 Teaching Policy 决策算法与数据契约

## 核心问题

在不使用 RL 的 v0.3，如何设计一个比大量 if/else 更可维护、但仍 deterministic、可解释、可 replay 的 policy engine？

## 研究范围

比较：

```text
pure rules
finite/state machine
decision table
rule engine
weighted scoring
multi-criteria decision analysis
supervised ranking/outcome model
contextual bandit（仅作为未来接口要求）
```

重点不是选“最先进算法”，而是确定：

- 哪些必须 hard filter；
- 哪些适合 state machine；
- 哪些适合 soft score；
- score 是否需要归一化/层级化；
- 如何避免策略 oscillation；
- 如何处理 low-confidence learner state；
- action 决策如何具备稳定 idempotency；
- policy config 如何 version/replay；
- future Bandit 需要从今天开始记录哪些字段。

## Future-learning 数据契约必须研究

即使 v0.3 不实施 Bandit，也应确认是否需要记录：

```text
context snapshot/version
available actions
hard-filtered actions + reason
selected action
raw/normalized scores
policy version
experiment assignment
propensity（若不是随机策略，语义如何定义）
short-term outcome
next independent outcome
delayed retention outcome
transfer outcome
time/hint cost
```

## 必须输出

1. v0.3 推荐决策架构；
2. hard-rule / state-machine / scorer 三层职责；
3. tie-break / fallback / conflict semantics；
4. DecisionTrace 最小字段增量；
5. anti-oscillation 机制；
6.未来 supervised/Bandit 所需的 logging readiness；
7. 明确“不实施 Bandit/RL”的理由与未来进入门槛。

# DR-03-04 学习效果验证与产品实验

## 核心问题

如何证明 Adaptive Teaching Loop 比固定策略或自由 LLM Tutor 更好？

Askora 的目标不是 engagement，而是：

```text
无提示独立成功
延迟保持
迁移
单位学习时间能力增益
```

## 必须研究

- ITS / adaptive tutoring 的常用实验与评价设计；
- immediate performance 与 learning gain 的区别；
- delayed post-test / transfer test；
- hint dependency / assistance dilemma；
- mastery false positive / false negative；
- within-subject、A/B、switchback、N-of-1 对个人系统的适用性；
- 单用户早期阶段如何避免“没有统计显著性就无法迭代”；
- expert policy review、scenario replay 与 synthetic learner simulation 可以证明什么、不能证明什么；
- LLM Tutor 的安全/忠实度指标如何作为 guardrail 而不是学习效果替代指标。

## 必须输出

1. v0.3 offline policy eval framework；
2. expert/scenario gold set；
3. strategy transition test matrix；
4. online / personal N-of-1 measurement plan；
5. immediate / delayed / transfer outcome schema；
6. guardrail metrics；
7. v0.3 release gate 中哪些指标是阻断性，哪些只做 telemetry baseline。

---

## 4. 证据质量要求

Deep Research 必须优先使用：

1. systematic review / meta-analysis；
2. peer-reviewed learning science / cognitive science / ITS 论文；
3. 高质量 RCT / controlled study；
4. 官方技术文档与公开算法论文；
5. 可信 ITS / adaptive-learning 产品公开设计；
6. LLM Tutor 最新实证论文；
7. 行业博客只能作为实践补充，不能独立支撑高影响教学规则。

每个关键结论必须标记：

```text
Evidence Strength: High | Medium | Low | Hypothesis
Applicability to Askora: Direct | Conditional | Indirect
```

需区分：

- 已被学习科学较稳定支持的原则；
- 只在特定学科/年龄/任务成立的结果；
- LLM Tutor 新兴且尚不稳定的证据；
- Askora 自己需要实验验证的设计假设。

## 5. 时间范围要求

经典学习科学理论不设置机械时间限制，但必须检查现代复现、meta-analysis 与边界条件。

AI Tutor / LLM / Agent / automated assessment 部分应重点覆盖截至研究执行日的最新工作，优先近 3 年，并检查是否存在 2025–2026 的更新证据。

1. v0.3 TeachingStrategy 最小集合是什么？
2. learner stage 是否只是 SYS05 policy feature，而不成为第二 LearnerState？
3. TeachingContext 最小字段是什么？
4. hard constraints 是什么？
5. scaffold/hint/answer exposure 的 canonical 语义是什么？
6. error taxonomy 最小集合是什么？

10. 如何防止 strategy oscillation？
11. 如何记录未来监督模型/Bandit 所需数据而不提前实施它们？

## 8. 研究停止条件

当以下条件全部满足后停止继续搜索，不以“更多文献”替代架构决策：

- 四项核心问题已有高/中质量证据覆盖；
- 关键反例/边界条件已识别；
- 候选方案 trade-off 已清晰；
- 足以确定 v0.3 baseline 与 out-of-scope；
- 剩余不确定性可以通过 Askora 自己的实验验证，而不是继续查资料解决。
