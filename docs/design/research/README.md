# Askora 设计研究资产索引

> 本目录保存“为什么这样设计”的研究依据与综合推导；正式产品/技术设计的唯一权威来源（Canonical Design）是 [`../AI学习系统算法与教学内核设计.md`](../AI学习系统算法与教学内核设计.md)。

## 1. 目录分层

```text
research/
├── evidence/   # Deep Research、论文、行业实践等证据层
├── synthesis/  # 跨证据综合、现状诊断、架构推导与研究结论
└── README.md   # 研究资产索引与治理规则
```

### evidence：证据层

保留高价值研究证据，不要求与最终设计内容完全去重。其职责是回答：**设计依据是什么、证据强度如何、有哪些边界与反例。**

### synthesis：综合研究层

用于保存跨证据推导后的结构性研究成果，回答：**这些证据对 Askora 架构意味着什么。**

当前主要资产：

## 2. 权威性规则

文档优先级固定为：

```text
Evidence
   ↓
Synthesis
   ↓
Canonical Design
   ↓
Implementation
```

具体规则：

1. `evidence/` 可以保留与其他文档重复的事实和论证，因为其价值是证据可追溯。
2. `synthesis/` 可以保留设计推导，但不得成为与正式设计并列的第二套规范。
3. `../AI学习系统算法与教学内核设计.md` 是第 4 章设计结论的唯一权威来源。
4. 若研究稿与正式设计冲突，以正式设计为准；研究稿用于解释历史依据和重新评审。
5. 实现代码不得直接以历史研究稿作为接口契约，除非正式设计明确引用。

## 3. 重复内容治理

不以“文本是否重复”作为删除标准，而以“是否存在多个权威来源”作为治理标准。

### 应保留

- 原始 Deep Research 证据；
- 论文、行业实践和证据分级；
- 关键架构推导、取舍理由和失败方案；
- 能够帮助未来重新验证设计决策的研究材料。

### 应合并或删除

- 仅因执行流程拆出的 `批次1/2/3/4` 等临时文件；
- 已完全被更高层文档吸收、且没有新增证据或推导价值的重复稿；
- 同一设计结论存在多个“最终版”“冻结版”“最新版”的情况。

## 4. Deep Research 文档生命周期

后续新增 Deep Research 文档统一按以下流程处理：

```text
Deep Research 原始结果
→ 判断属于 evidence 还是 synthesis
→ 语义化命名并入对应目录
→ 将采纳结论写入 Canonical Design
→ 删除无独立价值的阶段性/批次性文件
→ Git 历史保留原始版本与溯源
```

禁止长期使用 `批次1`、`阶段2`、`最终版2` 等执行过程命名作为正式研究资产名称。
