# 八类技术系统：记忆与复习调度证据

> 阶段：B｜统一研究资料库

## 1. 研究问题

1. 间隔复习的教育证据强度如何？
2. SM-2、Half-Life Regression、FSRS 的性质和适用范围是什么？
3. 复习调度如何与学习者建模、一般学习计划分离？
4. 如何避免把闪卡调度模型错误扩展到所有学习任务？

## 2. 间隔复习的基础证据

间隔效应具有长期、稳定的实验与元分析证据。Cepeda 等（2006）的定量综述表明分散练习相较集中练习具有可靠优势，并且最佳间隔会随最终保持间隔变化。

- 证据等级：`学术共识`
- 教育上有效：高
- Askora 适用：高

近期医学教育等领域的系统综述/元分析仍总体支持 spaced repetition，但不同研究在材料类型、间隔设置、测验方式和随访时间上存在明显异质性。

**重要边界**：

```text
“间隔复习有效”
≠
“某个具体调度算法对所有知识类型都已被因果证明最优”
```

## 3. 主动回忆必须与调度结合

`学术共识`

复习不是重新阅读原文，而应优先形成 retrieval event：

- 回忆定义；
- 解释概念；
- 解决问题；
- 重建步骤；
- 识别适用条件；
- 在陌生任务中应用。

`Askora 设计选择`：4.7 负责“何时需要复习”和遗忘风险，不负责决定具体教学表达；复习到期后由 4.6 排入计划，由 4.5 选择本次复习的 TeachingAction。

## 4. SM-2

SuperMemo SM-2 是经典启发式间隔算法。其历史价值在于简单、低数据要求和易实现。

- 证据等级：`行业实践`
- 工程成熟：高
- 个性化程度：低
- Askora 当前适用：baseline

**优势**：

- 状态少；
- 冷启动简单；
- 无需训练；
- 易解释和回放。

**限制**：

- 参数和更新规则较固定；
- 很难细致表达个体遗忘差异；
- 对不同知识类型的适配有限；
- 评分按钮本身可能包含主观噪声。

`Askora 设计选择`：保留 SM-2 或固定指数遗忘模型作为 benchmark/降级算法，而非长期默认上限。

## 5. Half-Life Regression（HLR）

Settles & Meeder（ACL 2016）提出可训练 spaced repetition model，用特征预测记忆 half-life，并在语言学习数据上进行验证。

- 证据等级：`研究证据`
- 技术可行：高
- 工程成熟：中高
- Askora 当前适用：中

**架构价值**：展示了从固定启发式规则走向“根据真实复习历史学习个体遗忘参数”的路径。

**局限**：原始研究主要面向语言记忆数据，不能直接视为通用概念学习最优模型。

## 6. FSRS

Free Spaced Repetition Scheduler（FSRS）是现代开源间隔调度算法，公开实现使用 Difficulty、Stability、Retrievability（DSR）等记忆状态，并支持根据复习历史优化参数。Anki 已在官方客户端中支持 FSRS，官方手册允许用户设置 desired retention 并优化参数。

- 证据等级：`行业实践` + `开源工程证据`
- 工程成熟：高
- 大规模真实使用：高
- 与传统算法的独立教育因果证据：仍需谨慎区分
- Askora 当前适用：高（作为复习调度核心候选）

FSRS 的状态概念：

```text
Difficulty     材料/卡片相对难度状态
Stability      记忆稳定性
Retrievability 当前回忆概率估计
```

Anki 官方文档明确描述 FSRS、desired retention、参数优化和 workload-retention trade-off。

### Askora 采用方式

`Askora 设计选择`

优先方案：

```text
FSRS-compatible memory state
+ Askora 自有 LearningEvent/Attempt 数据
+ 明确区分独立回忆与提示后成功
+ ReviewSchedule 版本化
```

但不能直接把“每个 KnowledgeUnit”都变成 Anki 卡片。

## 7. 不同知识类型的调度差异

`研究者推断` + `Askora 设计选择`

应至少区分：

### 7.1 事实/配对记忆

最接近传统 SRS 假设，可直接使用 recall success 更新 Stability/Retrievability。

### 7.2 概念理解

需要解释、辨别、反例和应用；单一“记住/忘记”不足以表示掌握。

复习时应轮换：

- 自由解释；
- 例子/反例辨别；
- 因果/机制解释；
- 新情境应用。

### 7.3 程序性技能

需要完整或局部执行步骤；复习结果应来自实际 performance，而非自评分。

### 7.4 迁移能力

不能只按经典记忆曲线调度；应在稳定掌握后周期性安排足够新颖的 transfer probe。

因此 4.7 只负责 schedule risk；4.4/4.3 决定结果如何构成 mastery evidence。

## 8. ReviewSchedule 的建议状态

`Askora 设计选择`

```text
ReviewSchedule {
  learner_id
  knowledge_unit_id
  memory_model
  model_version
  difficulty
  stability
  retrievability
  desired_retention
  last_valid_retrieval_at
  next_due_at
  review_priority
  evidence_quality
  updated_from_event_ids[]
}
```

注意：

- `ReviewSchedule` 不是 `LearnerState` 的复制；
- MasteryEstimate 由 4.3 拥有；
- memory scheduling state 由 4.7 拥有；
- 4.3 可读取 retrievability 作为特征，但不能改 next_due_at；
- 4.7 可读取 mastery/assessment evidence，但不能声明用户已掌握。

## 9. 有效复习结果的定义

`Askora 设计选择`

调度模型只能消费“符合最低质量的 retrieval evidence”。建议：

```text
有效成功：
- 学习者进行了真实提取
- 未提前看到完整答案
- 提示强度不超过允许阈值
- 评分置信度足够
```

下列事件不能与无提示成功等价：

- 先看答案再复述；
- 强提示后补最后一步；
- 多次猜测直到命中；
- 用户点击“我会了”；
- LLM 主观认为“看起来理解了”。

## 10. 调度目标与时间成本

Anki/FSRS 的 desired retention 体现一个重要产品权衡：更高目标保持率意味着更多复习工作量。

`Askora 设计选择`：

4.7 产生推荐到期时间时应输出：

- recall risk；
- expected benefit；
- overdue penalty；
- uncertainty。

4.6 再结合用户时间预算、目标截止期、新学任务和迁移任务决定“今天是否执行”。

因此：

```text
4.7：什么时候最好复习
4.6：在全部任务约束下，今天实际安排什么
```

## 11. 冷启动

`Askora 设计选择`

新用户/新知识点无历史时：

1. 使用 population/default parameters；
2. 根据内容类型、难度和首次 performance 初始化；
3. 收集几次有效 retrieval event 后逐步个性化；
4. 参数不确定度高时采用保守间隔；
5. 不为追求“个性化”过早拟合极少数据。

## 12. 评估框架

### 12.1 预测指标

- Log Loss；
- Brier Score；
- calibration error；
- recall probability calibration。

### 12.2 调度指标

- desired vs observed retention；
- overdue rate；
- reviews per retained unit；
- workload；
- relearning frequency。

### 12.3 教育结果

- 延迟独立回忆；
- 概念应用；
- 迁移成功；
- 单位学习时间长期保持增益。

一个模型预测 recall 更准，并不必然意味着对所有学习目标更好。

## 13. 技术路线

### MVP

- 使用简单稳定模型或 FSRS-compatible scheduler；
- 记录完整 review event；
- 区分 Again/Hard/Good/Easy 类信号时必须映射到 Askora 的真实证据质量；
- ReviewSchedule 单独持久化；
- 允许手动延期/提前，但保留原建议与实际执行记录。

### 增强版

- 个体参数优化；
- 不同知识类型分模型；
- 预测校准；
- workload-retention 优化；
- 与 LearningPlan 联动。

### 成熟版

- 多目标 schedule optimization；
- transfer probe scheduling；
- 对长期策略做严格反事实评估。

### 当前不建议

- 直接训练 RL 取代成熟 SRS；
- 把点赞/自信程度当真实 recall；
- 用一个 forgetting probability 代表完整 mastery；
- 让 4.6 自己维护另一套复习时间。

## 15. 证据缺口

- FSRS 在开放式概念学习、程序技能和迁移任务上的最优映射尚需 Askora 验证。
- 自动评分误差会污染复习状态，因此 4.4 的 AssessmentResult confidence 必须进入 4.7 更新规则。
- “什么时候测迁移”与“什么时候做记忆复习”不是同一调度问题；迁移调度仍需实验。
