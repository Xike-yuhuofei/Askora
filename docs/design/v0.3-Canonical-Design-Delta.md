## 1. Delta Scope

v0.3 只解决一个核心问题：

> **在 `LearningActivity` 已由 SYS06 确定后，Askora 如何基于当前可审计证据决定“此刻怎么教”，并随着新证据增加、维持、降低或撤除支架，同时保证决策可解释、可重放、可测试，并能形成真实学习效果验证的数据基础。**

v0.3 的核心增量不是新建第九个教学系统，而是把现有 SYS05 Teaching Policy 收敛为：

```text
Immutable TeachingContext Snapshot
→ Typed Hard Constraints
→ Derived TeachingStage
→ Typed Candidate Generation / Decision Table
→ Feature Builder
→ Normalized Weighted Scoring
→ Anti-Oscillation Gate
→ Deterministic Tie-break
→ Immutable TeachingAction
→ DecisionTrace
→ Evidence / Execution / Attempt / Assessment
→ LearnerState Projection
→ Outcome Observation
→ Next Policy Evaluation
```

## 4. Teaching Strategy Ontology Delta

### 4.1 Top-level StrategyFamily

v0.3 顶层仅允许：

```text
EXPLICIT_INSTRUCTION
GUIDED_PRACTICE
FADING_PRACTICE
RETRIEVAL_PRACTICE
ERROR_REMEDIATION
TRANSFER_CHALLENGE
```

这些是 Askora 的工程 ontology，用于表达相对稳定的 teaching episode / control intent；不是宣称教育科学天然存在唯一六分类。

### 4.2 Four-layer model

```text
StrategyFamily
    = 相对稳定的教学 episode/control intent

TeachingAction
    = SYS05 在 exact TeachingContext + exact PolicyBundle 下生成的 immutable executable decision

InteractionMove
    = action 内的一次局部 tutor operation

ActionModifier
    = 不改变 StrategyFamily 的横切教学语义
```

`DIRECT_INSTRUCTION`、`WORKED_EXAMPLE`、`SOCRATIC_PROBE`、`SELF_EXPLANATION_PROMPT`、`METACOGNITIVE_CHECK` 等不得再次升级为 top-level StrategyFamily。

`PRODUCTIVE_FAILURE` 不进入 v0.3 selectable baseline。

### 4.3 Legacy ontology migration

历史九类 strategy 只允许 compatibility read/audit，并显式映射到六族 + move/modifier。任何不可无损映射的历史记录必须标注 ambiguity/replay status；禁止永久 dual truth。

该 breaking decision 由 `ADR-0001-teaching-strategy-ontology.md` 固化。

## 5. TeachingContext & TeachingStage Delta

### 5.1 TeachingContext

`TeachingContext` 冻结为一次 policy evaluation 的 immutable decision-input snapshot。

它：

- 通过 exact-version refs 引用 SYS01/03/04/06/07 等 owner 的事实或状态；
- 保存 decision time、context schema version 与 deterministic fingerprint；
- derived feature 必须保留 source refs、availability、confidence 与 feature version；
- 不拥有第二份 LearnerState、AssessmentResult、LearningPlan 或 ReviewSchedule truth；
- canonical replay 不得隐式读取 mutable live state，也不得重新调用在线 LLM 还原决策输入。

所有可缺失语义至少区分：

```text
AVAILABLE
MISSING
STALE
LOW_CONFIDENCE
NOT_APPLICABLE
```

禁止用 `0`、空字符串或伪默认值表达未知。

### 5.2 TeachingStage

Canonical vocabulary：

```text
DIAGNOSE
EXPLICIT_INSTRUCTION
GUIDED_PRACTICE
FADING_PRACTICE
RETRIEVAL_PRACTICE
DELAYED_RETRIEVAL
ERROR_REMEDIATION
TRANSFER_CHALLENGE
```

定义：

```text
TeachingStage = f(TeachingContext, PolicyBundle)
```

它是当前 activity 的 transient policy-control feature：

- 不是 LearnerState；
- 不是 MasteryState；
- 不是长期学习阶段；
- 不创建第二套 learner state machine truth；
- MAY 进入 DecisionTrace；
- MAY 有可丢弃、可重建 cache/projection；
- stage definitions / guards / priority / fallback 可以版本化。

SYS03 历史 `learning_stage_summary` 必须迁移/重命名为非教学策略含义的 `learner_progress_summary` 或等价字段。

## 6. Error Diagnosis → Remediation Delta

### 6.1 Canonical ErrorType

v0.3 仅允许：

```text
KNOWLEDGE_GAP
CONCEPTUAL_MISCONCEPTION
METHOD_SELECTION
EXECUTION
RETRIEVAL_FAILURE
TRANSFER_FAILURE
EXPRESSION_FORMAT
UNKNOWN
```

### 6.2 Ownership boundary

```text
Misconception definition      → SYS01
single-attempt error/evidence → SYS04
MisconceptionHypothesis       → SYS03
remediation TeachingAction    → SYS05
```

`assessment_confidence` 与 `diagnostic_confidence` 必须独立表达。

`UNKNOWN` 是合法结果。现有证据不能区分会导致不同 remediation 的多个解释时，应允许 bounded diagnostic probe；禁止为 enum 完整性强制猜错因。

### 6.3 Error does not select action directly

错误诊断只能影响候选生成、hard constraint、feature 与 scoring：

```text
ErrorType / diagnostic evidence
→ remediation candidates
→ SYS05 policy evaluation
→ TeachingAction
```

禁止：

```text
ErrorType
→ hard-coded final TeachingAction
```

## 7. Assistance / Exposure / Independent Validation Delta

Canonical assistance 采用四个正交维度：

```text
scaffold_control = NONE | LOW | MEDIUM | HIGH
hint_specificity = NONE | ORIENTATION | CONCEPTUAL_STRATEGIC | SUBGOAL | PARTIAL_STEP | BOTTOM_OUT
answer_exposure = NONE | PARTIAL | COMPLETE
assistance_state = INDEPENDENT | ASSISTED | ANSWER_EXPOSED
```

Ownership：

- SYS05 定义 allowed envelope；
- SYS02 / SYS08 MAY 收紧，MUST NOT 扩大；
- SYS04 记录 learner 实际经历的 assistance/exposure；
- SYS03 根据实际经历决定 evidence eligibility/weight。

核心不变量：

```text
assisted success ≠ independent success
answer-exposed success ≠ independent mastery evidence
```

`ASSISTED` 或 `ANSWER_EXPOSED` success 后，SYS05 必须建立：

```text
INDEPENDENT_VALIDATION_REQUIRED
```

该 obligation 是 SYS05 policy-control semantics，不是 MasteryState。只有后续 fresh independent Attempt 实际发生并形成有效证据后，才能满足独立验证要求。

## 8. Constrained Deterministic Policy Delta

### 8.1 Canonical stack

v0.3 SYS05 冻结为：

```text
TeachingContext Snapshot
→ Typed Hard Constraints
→ Derived TeachingStage
→ Typed Candidate Generation / Decision Table
→ Feature Builder
→ Normalized Weighted Scoring
→ Anti-Oscillation Gate
→ Deterministic Tie-break
→ Immutable TeachingAction
→ DecisionTrace
```

同一：

```text
TeachingContext
+ PolicyBundle
+ ExperimentAssignment
```

必须得到同一 semantic TeachingAction。

### 8.2 Rule classes

必须严格区分：

```text
Hard Constraint
Soft Preference
Experiment Guardrail
```

Hard Constraint：

- 只负责 admissibility / obligation / fail-safe；
- 不得被 weighted score 抵消；
- 不得被 LLM override；
- 不得被 experiment 恢复被过滤动作；
- conflict 必须显式检测。

Soft score 只比较已经合法的候选动作。

### 8.3 Required hard-constraint families

v0.3 至少覆盖：

1. Assessment Integrity；
2. Answer Exposure Integrity；
3. Prerequisite Safety；
4. Repeated Failure Ceiling；
5. Independent Success Constraint；
6. Low-confidence Conservatism；
7. Objective Ownership；
8. Model/LLM Override；
9. Unsupported Configuration；
10. Hard-rule Conflict；
11. User Direct Answer bounded override。

用户明确请求答案可以改变候选 move，但不得绕过 active assessment integrity、安全、exposure 约束和后续 independent-validation obligation。

### 8.4 Anti-oscillation

Strategy/major action transition 必须由 material evidence 驱动，例如新的 AssessmentResult、independent Attempt、probe result、LearnerState update、explicit user request、prerequisite evidence、exposure event 或 meaningful review/delay transition。

以下不能单独触发 transition：

- 又多一轮聊天；
- policy 又执行一次；
- LLM wording 改变；
- wall clock 多几秒。

冻结机制：

```text
material-evidence gate
+ sticky continuity
+ minimum dwell by evidence opportunity
+ hysteresis / switch margin
+ versioned transition priority
+ repeated-failure override
```

### 8.5 PolicyBundle

Policy 配置必须 immutable/versioned，并至少 pin：

```text
schema_version
policy_version
hard_rule_set_version
stage_mapper_version
candidate_table_version
feature_schema_version
normalization_version
weight_profile_version
anti_oscillation_profile_version
tie_break_version
fallback_profile_version
subject_profile_version
content_digest
```

Publish immutable；activation atomic；历史 bundle 保留用于 replay/audit。禁止 executable DSL、embedded Python、free-form runtime rules 与 LLM-generated policy rules。

该架构由 `ADR-0002-constrained-deterministic-teaching-policy-architecture.md` 固化；生产 profile 来源/激活规则继续服从 `ADR-0003-policy-runtime-profile-source-and-activation.md`。

## 9. DecisionTrace / Replay / Probability Delta

### 9.1 Decision vs outcome

```text
DecisionTrace
= 当时为什么做出该决定

OutcomeObservation
= 后来测到了什么
```

Outcome 不得回写篡改旧 DecisionTrace。

### 9.2 Replay boundary

完整 replay 必须固定或引用：

- exact TeachingContext owner versions；
- exact PolicyBundle；
- stage mapper / candidate table / feature schema / normalization / weights；
- anti-oscillation profile；
- deterministic tie-break；
- relevant experiment assignment；
- decision time。

缺失历史版本时必须显式标记 `PARTIAL` / `NON_REPLAYABLE` 或等价状态，禁止伪造 full replay。

### 9.3 Probability semantics

v0.3 canonical runtime 是 deterministic policy：

```text
behavior_policy_type = DETERMINISTIC
action_propensity = null
```

不得把 deterministic action propensity 伪造为 `1.0`。

必须区分：

```text
ExperimentAssignment.assignment_probability
≠ TeachingAction action_propensity
```

前者是实验随机分配概率；后者是 behavior policy 对 action 的选择概率。二者不可混用。

## 10. Outcome / Experiment Data Delta

v0.3 additive 引入：

```text
TeachingEpisode
LearningTrajectory
OutcomeObservation
ExperimentAssignment
```

这些对象服务于 analytics / experiment / attribution，不建立第九个 domain truth owner。

### 10.1 Attribution integrity

Delayed outcome 禁止自动 last-touch 给最后一个 TeachingAction。

允许的 attribution scope 必须显式区分 direct、episode-associated、trajectory-associated、experimentally-causal 与 unattributable 等语义。只有满足实验识别条件时，才能宣称 experimentally causal。

### 10.2 Learning outcome hierarchy

Askora 的四个核心 learning outcome family 冻结为：

1. **无提示独立成功**；
2. **延迟保持 / delayed independent performance**；
3. **迁移 / transfer**；
4. **单位学习时间能力增益 / unit-time capability gain**。

engagement、conversation turns、likes、hint count、即时 assisted correctness 等只能作为 process / experience diagnostics，不能成为主要学习目标。

核心测量原则：

> **Learning must be measured after assistance is withdrawn.**

每个具体实验必须预先指定 primary outcome；任何具体延迟窗口、novelty threshold、practical harm margin 都是版本化实验参数，不是固定科学常数。

## 11. Verification & Release Delta

v0.3 采用分层证据框架：

```text
Layer 1 — Offline Policy Verification
Layer 2 — Real-user Learning Measurement
Layer 3 — N-of-1 Comparative Experiment
Layer 4 — Evolution Gate
```

### 11.1 Offline evidence boundary

Scenario Gold Set、hard-constraint tests、transition replay、property/metamorphic tests、synthetic learner stress tests 可以证明：

- engineering correctness；
- policy correctness；
- deterministic replay；
- owner / hard-rule integrity。

它们**不能证明真实 learning efficacy**。

### 11.2 Real-user evidence

v0.3 单真实用户阶段只能形成 individual-level directional/causal evidence，不得宣称 population-wide superiority。

Primary online comparison：

```text
B2 = LLM strategy judgment baseline
vs.
B3 = Askora deterministic Adaptive Teaching Policy
```

B2 仍必须位于相同 hard policy shield 和 action vocabulary 内。

### 11.3 Release Gate

Release Gate 冻结为三个主层级：

```text
Engineering Correct
+
Policy Correct
+
Learning Evidence
```

其中 learning evidence 必须区分：

- no learning harm；
- directional individual learning evidence；
- experimental data foundation correctness；
- evidence sufficiency。

没有足够真实学习证据时，正确状态是：

```text
LEARNING_EVIDENCE_INSUFFICIENT
```

而不是把 synthetic learner、expert agreement、scenario replay 或 engagement 指标包装成学习效果证明。

## 14. Migration & Compatibility Rules

### 14.1 General rule

```text
Canonical v0.3 writer
→ only writes v0.3 semantics

Legacy adapter
→ compatibility read / audit only
```

禁止永久 dual-write / dual-truth。

### 14.2 Required migration behavior

- historical strategy：显式映射到 six StrategyFamily + move/modifier；ambiguous mapping 必须标记；
- historical TeachingAction：非无损迁移必须标记 partial semantics/replayability；
- integer `scaffold_level` / `hint_level` / old exposure scale：只允许 read adapter，lossy/unknown 必须显式；
- legacy Socratic state machine：不得成为 final policy owner；
- old executable/free-form policy config：不得在 v0.3 canonical runtime 执行；
- old propensity：只有 provenance 能证明含义时才可解释；否则 unknown/null + migration reason；
- historical replay：缺少 exact version refs 时必须保留 partial/non-replayable 状态。

Retirement condition 必须由 active writer/readers 全部切换、历史记录迁移或具有明确 audit/replay 状态后再满足。

## 15. Explicitly Deferred to v0.4+

以下内容**不进入 v0.3 canonical runtime**：

- Contextual Bandit；
- Offline RL / Online RL；
- learned policy 直接替代 deterministic canonical policy；
- Deep KT 作为 canonical learner truth；
- complex IRT-CAT；
- open-world misconception discovery；
- automatic multi-error causal decomposition；
- generic Productive Failure selectable strategy；
- always-on Socratic tutor；
- free-form LLM TeachingAction ownership；
- generic executable policy DSL / rule engine；
- synthetic learner 作为真实 learning efficacy evidence；
- school/population-level superiority claims without adequate data。

未来是否引入这些能力，必须以正确数据基础、stable outcome linkage、真实学习证据和新的 Canonical Design/ADR 为前置条件。
