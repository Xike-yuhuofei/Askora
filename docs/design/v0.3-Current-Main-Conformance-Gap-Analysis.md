## 1. Executive Verdict

### 1.1 总结论

当前 `main` **不是完整 v0.3 runtime conformant**。

冻结判定：

```text
Core Contract / Ownership Foundation:      CONFORMANT
Single-decision Policy Kernel:             CONFORMANT
SYS08 Tightening-only Execution:           CONFORMANT
Validation Obligation Semantics:           CONFORMANT
Policy Runtime Artifact / Versioning:      CONFORMANT
Production Sequential Policy Integration: NON-CONFORMANT
Production TeachingContext Hydration:      PARTIAL / REQUIRED
Current Engineering CI:                    FAILED
Learning Evidence:                         LEARNING_EVIDENCE_INSUFFICIENT

Overall:
POLICY_CORRECTNESS_GATE_FAILED
ENGINEERING_GATE_FAILED
```

最重要的问题不是“缺少 anti-oscillation 算法”。算法已经存在于：

`apps/backend/app/domains/teaching_policy/sequential.py`

真正缺口是：

> **生产 v0.3 adaptive path 没有调用它。**

`LearningOrchestrationFacade` 明确是 production application entry，但 `_execute_adaptive_turn()` 当前直接调用 `TeachingPolicyKernel.decide()`。因此 production B3 runtime 实际执行的是 single-decision kernel，而不是 Spec 冻结的完整 sequential policy stack。

这直接违反 `SYS05-230` / `DOD-210` / `DOD-211` 的 anti-oscillation 与 no-policy-bypass 要求，属于 **Policy Correctness blocker**。

### 1.2 不应误判为缺口的事项

以下虽然在代码中仍存在，但本次审计确认**不能仅因存在就判为 v0.3 violation**：

- legacy Socratic engine / selector：当前明确标记为 v0.2 compatibility rendering/move adapter，不能产生 `TeachingActionV03`；
- DKT：当前明确为 challenger/auxiliary，`CANONICAL_WRITE_ENABLED = False`；
- legacy v0.2 facade path：只要不能产生 canonical v0.3 TeachingAction，并且不接管 v0.3 owner，可继续作为兼容路径；
- `LEARNING_EVIDENCE_INSUFFICIENT`：这是诚实的 Learning Evidence 状态，不是 Engineering failure；
- `TeachingPolicyKernel` 本身：它作为 pure single-decision evaluator 是合理分层，不应删除或把 anti-oscillation 强塞回 kernel。

## 4. Verified Conformant Foundations

### 4.1 Canonical v0.3 public vocabulary — PASS

`apps/backend/app/contracts/adaptive.py` 已明确：

```text
StrategyFamily = six only
ErrorType = 7 + UNKNOWN
TeachingStage = canonical derived vocabulary
ScaffoldControl / HintSpecificity / AnswerExposure / AssistanceState = orthogonal axes
```

并明确 v0.3 writer 不写 legacy integer support fields 或旧九策略族。

### 4.2 Single-decision deterministic kernel — PASS

`TeachingPolicyKernel` 是 pure evaluator：

```text
validate
→ hard constraints
→ derive stage
→ candidate generation
→ feature builder
→ scoring
→ stable selection
→ immutable action
→ DecisionTrace
```

它不读取 mutable runtime、不调用 LLM、不随机选择，并正确记录：

```text
behavior_policy_type = DETERMINISTIC
action_propensity = null
anti_oscillation_decision = null
transition_reason = EXEC009_SINGLE_DECISION_KERNEL
```

这里的 `anti_oscillation_decision = null` 本身不是 kernel bug；它清楚表达“本对象只负责 single decision”。问题在于 production composition 没有继续进入 sequential wrapper。

### 4.3 Sequential anti-oscillation implementation — IMPLEMENTED BUT NOT WIRED

`SequentialTeachingPolicy` 已实现：

- exact previous TeachingAction ref validation；
- material evidence classification；
- sticky continuity；
- evidence-opportunity minimum dwell；
- switch-margin hysteresis；
- repeated-failure override；
- hard-constraint precedence；
- explicit-user-request transition；
- transition priority；
- anti-oscillation DecisionTrace payload；
- deterministic next `SequentialPolicyState`。

因此当前不需要重新研究 anti-oscillation 算法，也不需要新建一套状态机。

### 4.4 SYS08 tightening-only — PASS

`AdaptiveExecutionService` 对 untrusted renderer/model proposal 执行：

- strategy override denied；
- InteractionMove expansion denied；
- modifier override denied；
- scaffold expansion denied；
- hint expansion denied；
- answer exposure expansion denied；
- unauthorized tool denied；
- unverified evidence denied；
- actual exposure under-report 检测；
- violation → tightening fallback。

SYS08 没有取得 TeachingAction owner。

### 4.5 Independent validation obligation — PASS

它没有把“计划中的 allowed assistance”误写成 learner truth。

### 4.6 Policy runtime artifact governance — PASS

- digest verification；
- immutable bundle record；
- activation resolution；
- profile ↔ bundle version/digest matching；

## 5. Gap Register

## GAP-V03-001 — Production Adaptive Path Bypasses SequentialTeachingPolicy

**Severity：BLOCKER**  
**Gate：Policy Correctness / Engineering no-policy-bypass**  
**Status：OPEN**

### Expected

根据 `SYS05-230`：

```text
TeachingContext
→ Hard Constraints
→ TeachingStage
→ Candidate Generation
→ Feature Builder
→ Normalized Scoring
→ Anti-Oscillation Gate
→ Deterministic Tie-break
→ TeachingAction
→ DecisionTrace
```

连续决策必须使 previous action + material evidence 参与 transition permission。

### Current

`LearningOrchestrationFacade._execute_adaptive_turn()` 当前直接：

```python
self._policy_kernel.decide(...)
```

随后立即进入 retrieval / SYS08 execution。

`SequentialTeachingPolicy` 没有进入 facade 的 adaptive production path。

Book-to-Learning 的 `start_teaching_round()` 也直接构造 `CanonicalTurnRequest` 交给该 facade，因此没有其他上层 sequential wrapper 可以补偿这一缺口。

### Consequence

当前 runtime 可能出现：

- 没有 material new evidence 也重新选择新的 action；
- minimum dwell 不生效；
- switch-margin hysteresis 不生效；
- repeated-failure sequential override 不按 frozen transition layer 生效；
- DecisionTrace 缺少真实 `anti_oscillation_decision`；
- OPVE/unit sequential tests 与真实 production composition 脱节。

依据 `DOD-211`，policy bypass / illegal oscillation 必须阻断 Policy Correctness Gate。

### Required Resolution

不得重写 kernel。应保持：

```text
TeachingPolicyKernel
= single-decision pure evaluator

SequentialTeachingPolicy
= production sequential transition wrapper
```

生产 composition 必须做到：

1. 第一 canonical decision 在无 previous action 时允许走 kernel/bootstrap semantics；
2. 后续 decision 在存在 previous action 时必须进入 `SequentialTeachingPolicy`；
3. sequential wrapper 必须获得 exact previous action、fixed decision time、material evidence signals 与可重建 sequential state；
4. resulting `TeachingAction + DecisionTrace` 才能进入 SYS02/SYS08；
5. ordinary/streaming/book learning 的 canonical adaptive paths 不得出现第二种 final policy path；
6. 若实现发现当前 Spec 对 sequential state 的 durable/reconstructible representation 不足以无歧义落地，必须报告 `BLOCKED_BY_SPEC_GAP`，不得自行新建第二 truth。

## GAP-V03-002 — Book TeachingContext Does Not Hydrate Available Sequential Evidence

**Severity：REQUIRED / coupled with GAP-V03-001**  
**Gate：Policy Correctness / TeachingContext completeness**  
**Status：OPEN**

### Expected

`SYS05-210` 要求 TeachingContext snapshot 语义覆盖存在且可用的：

- recent AssessmentResult / correctness / confidence；
- ErrorType / diagnostic evidence；
- assistance/scaffold/hint/exposure history；
- independent/assisted success history；
- previous TeachingAction / outcomes；
- delayed/review/transfer evidence；
- explicit user request 等。

“字段允许 MISSING”不等于“已有 canonical evidence 仍可永久不装载”。

### Current

`BookLearningApplication._teaching_context()` 当前主要 hydrate：

- LearningGoal；
- LearningPlan；
- LearningActivity / Objective；
- latest LearnerState；
- latest MasteryEstimate；
- time budget。

大量 sequentially relevant fields 直接保持 `MISSING` 或模型默认空值。

尤其后续 teaching round 没有显式 hydrate：

```text
previous_teaching_action_ref
previous_action_outcome_refs
assistance_history_summary
scaffold_history
hint_history
answer_exposure_history
recent_assessment_result_ref
correctness_score
assessment_confidence
error_type / diagnostic_confidence
independent_success_history / assisted_success_history
```

现有 Book-to-Learning E2E 在第二 teaching turn 前创建了新的 independent AssessmentResult / MasteryEstimate，但断言重点是“新的 mastery estimate 出现在 source_refs”，没有验证 previous action / recent assessment / material evidence 被装载到 sequential decision input。

### Consequence

即使把 `SequentialTeachingPolicy` 接回 production，如果 context/signals 仍未 hydrate，sequential layer 也无法可靠判断：

- 是否有 material evidence；
- 是否满足 dwell opportunity；
- repeated failure；
- previous action legality；
- fresh independent success；
- assistance/exposure transition；
- diagnostic transition。

### Required Resolution

下一实现任务必须复用已有 canonical repositories / immutable records，构造一个**可 replay 的 sequential input projection**。

不得：

- 创建第二 LearnerState；
- 把 chat turn count 当 evidence opportunity；
- 从 LLM 文本猜 previous outcome；
- 把 missing history 伪装成 0；
- 建新的“万能 TutorState”同时拥有 learner/action/plan/review truth。

如果已有 immutable DecisionTrace / TeachingAction / AssessmentResult / ActualAssistance / LearnerState records 足够，则应重建 projection；只有确实存在公共 durable schema 缺口时才升级为 Spec Gap。
